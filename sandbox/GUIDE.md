# Руководство по созданию практических заданий

> **Назначение:** Стандарт для создания файлов упражнений в `js_sandbox` и `next_sandbox` по каждой теме курса.  
> **Стек:** TypeScript · React · Next.js App Router

---

## Структура файлов

Для каждой темы создаются **два файла в двух sandbox-окружениях**:

```
sandbox/
├── js_sandbox/topics/topic_N/
│   ├── exercises.ts   ← задания с TODO-заглушками
│   └── solutions.ts   ← решения с пошаговыми объяснениями
│
└── next_sandbox/lessons/topic_N/
    ├── exercises.ts   ← задания в контексте React/Next.js
    └── solutions.tsx  ← решения + React-компоненты для демо
```

`N` — номер темы из [`general/02_topic_list.md`](../general/02_topic_list.md).

---

## Источник материала

Перед созданием заданий прочитай соответствующий раздел в `topics/`:

| Раздел темы | Что брать для заданий |
|---|---|
| **Теория** | Ключевые механизмы → задания на предсказание вывода |
| **Связь со стеком** | React/Next.js паттерны → задания `next_sandbox` |
| **Лучшие паттерны** | ❌ антипаттерн → задание "исправь баг" |
| **Практическое задание** | Готовое условие → раздел "Реализация утилит" |
| **Решение** | Эталонный код → `solutions.ts` с дополненными объяснениями |

## Четыре типа заданий

### Тип 1 — Предсказание вывода

**Когда:** для тем с неочевидным порядком выполнения (Event Loop, Hoisting, Scope).

```typescript
/**
 * Задание 1.1 — <Краткое название>
 *
 * // Вывод: ?
 *
 * Объясни почему каждая строка выводится именно в этот момент.
 */
export function predict_1_1(): void {
  // ... код
}
```

**Правила:**
- Код должен быть запускаемым (`export function`, не сниппет)
- Студент записывает ответ в комментарий `// Вывод: ?` до запуска
- В `solutions.ts` — пошаговая трассировка с состоянием очередей

---

### Тип 2 — Реализация утилиты

**Когда:** для тем с конкретным алгоритмом из раздела "Практическое задание".

```typescript
/**
 * Задание 2.N — <Название функции>
 *
 * <Одно предложение: что делает>
 *
 * Пример:
 *   <конкретный вызов и ожидаемый результат>
 *
 * Подсказка: <алгоритмическая подсказка, не спойлер>
 */
export function myFunction(/* параметры */): ReturnType {
  // TODO: реализуй
  throw new Error("Not implemented");
}
```

**Правила:**
- `throw new Error("Not implemented")` — обязательно, падает при запуске не реализованной функции
- Подсказка намекает на подход, не раскрывает решение
- В примере — реальные значения, не абстракции

---

### Тип 3 — Найди и исправь баг

**Когда:** берётся ❌-антипаттерн из раздела "Лучшие паттерны".

```typescript
/**
 * Задание 3.N — <Название проблемы>
 *
 * BUG: <что именно не так, видимый симптом>
 *
 * Вопросы:
 *   1. Объясни ТОЧНО почему возникает баг
 *   2. Реализуй <fixedFunction> с исправлением
 */
export async function brokenFunction(/* ... */): Promise</* ... */> {
  // BUG: <inline-комментарий на строке с ошибкой>
  // ... баги код
}

export async function fixedFunction(/* ... */): Promise</* ... */> {
  // TODO: реализуй корректную версию
  throw new Error("Not implemented");
}
```

**Правила:**
- Баги код — рабочий TypeScript, который компилируется, но ведёт себя неправильно
- Вопросы: сначала "объясни" (понимание), потом "реализуй" (код)
- В `solutions.ts` — объяснение причины бага перед исправлением

---

### Тип 4 — Паттерн (продвинутый)

**Когда:** для тем с нетривиальным best practice (worker pool, debounce, memoize).

```typescript
/**
 * Задание 4.N — <Название паттерна>
 *
 * <Описание задачи и зачем она нужна в production>
 *
 * Пример:
 *   <использование интерфейса>
 *
 * Подсказка: <ключевая идея без деталей реализации>
 */
export function createSomething(/* ... */): SomeInterface {
  // TODO:
  // 1. <первый шаг>
  // 2. <второй шаг>
  throw new Error("Not implemented");
}
```

**Правила:**
- TODO-комментарии внутри функции намечают структуру, не код
- В `solutions.ts` — объяснение почему паттерн именно такой (инсайт из курса)

## Специфика `next_sandbox`

`exercises.ts` и `solutions.tsx` в `next_sandbox/lessons/topic_N/` фокусируются на **React/Next.js проявлениях** темы из раздела "Связь со стеком".

### Что добавляется в `solutions.tsx`

- `"use client"` в начале файла (компоненты используют хуки)
- React-компонент на каждый ключевой паттерн — интерактивная демонстрация
- Импорты `useState`, `useEffect`, `useCallback` и т.д.

### Маппинг тема → Next.js задания

| Тема | Типичные задания для `next_sandbox` |
|---|---|
| Event Loop | `Promise.all` в Server Component, stale closure в `useEffect`, debounce |
| Hoisting/TDZ | `const`/`let` в React-паттернах, инициализация хуков |
| Замыкания | `useState` под капотом, `useCallback`/`useMemo`, утечки памяти |
| Promise | Параллельный fetch, `loading`/`error` состояния, `Promise.allSettled` |
| async/await | Server Actions, `Suspense`, обработка ошибок в Next.js |
| Прототипы | Расширение классов компонентов (редко), TypeScript-паттерны |

## Запуск

```bash
# Запуск упражнений (показывает вывод разделов 1 и 2)
npx tsx sandbox/js_sandbox/topics/topic_N/exercises.ts

# Запуск решений (полная демонстрация всех ответов)
npx tsx sandbox/js_sandbox/topics/topic_N/solutions.ts

# Из корня через npm-скрипты (если добавлены в root package.json)
npm run topic:N
```
