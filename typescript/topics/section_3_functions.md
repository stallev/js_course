### Теория с аналогией

**Аналогия: рецепт с перечнем продуктов и блюда на выходе**

Параметры — продукты с типом. `return` — блюдо. `void` — рецепт «сделай побочный эффект, ничего не возвращай» (`console.log`, смена текста в DOM).

```typescript
function area(width: number, height: number): number {
  return width * height;
}

function logStatus(ready: boolean): void {
  console.log(ready ? "готово" : "ждём");
}

const paint = (title: string): string => `Тема: ${title}`;
```

Стрелки — 🔗 Junior тема 12; типы пишутся у параметров и после `=>` для возвращаемого, либо дай вывести из `return`.

Имя формы функции — `type`, как в теме 6:

```typescript
type Mapper = (n: number) => string;
```

Необязательный параметр: `unit?: string` в конце списка. Значение по умолчанию `unit = "м²"` тоже сужает дыру.

Если написал `: number`, а ветка ничего не возвращает — `tsc` красный. Это полезно.

### Где это в реальном коде

Обработчик клика в этом слое типизируй сам: `(event: Event) => void` или проще обёртка без `event`, если не нужен (🔗 Junior тема 18). Колбэк `map`: `(lesson: Lesson) => string`.

### Паттерны

❌ Не указывать возврат и случайно вернуть разное (`number` и `undefined`)  
✅ Явный `: number` или всегда `return`  
Почему: вызов ждал число.

❌ `: any` на параметре «потом разберём»  
✅ Реальный тип или union  
Почему: иначе тема 1 не работает.

❌ Путать `void` и `undefined`  
✅ `void` — «возврат не используй»; функция может не иметь `return`  
Почему: так помечают логгеры и обработчики.

### Вопросы

**Q1: Где обязательна аннотация — у `const n = 1` или у параметра?**  
У параметра. Снаружи вызова компилятор не видит, что передадут: вывода нет. `const n = 1` выводится сам (тема 3). Пустой массив и явный union на границе — тоже места для аннотации. Внутри тела функции чаще хватает вывода из `return`.

**Q2: Можно ли тип функции записать как `type`?**  
Да: `type Mapper = (n: number) => string`. Это как раз случай темы 6: не объект, значит не `interface`. Имя можно поставить на колбэк `map`, на обработчик, на поле объекта. В runtime имени нет — стирается.

**Q3: Что если забыл `return` при аннотации `: number`?**  
`tsc` красный: обещали число, ветка ничего не вернула. Без аннотации возврата вывод часто станет `void`, и ошибка всплывёт уже у вызывающего. Явный возврат ловит дыру раньше. Пустой `return;` — это `undefined`, не число.

**Q4: Стрелка и `function` — разные типы?**  
Для этого слоя нет: оба описываются списком параметров и возвратом. `this` не ядро, как в Junior. Различие синтаксиса Junior темы 12 остаётся про запись, не про другую систему типов. Не учи «стрелка всегда void».

**Q5: Несколько параметров одного типа — можно одним словом?**  
Нет: `add(a: number, b: number): number`. Каждый параметр — своя аннотация. Не пиши `add(a, b: number)`. Rest-параметр `...xs: number[]` — отдельная история, в слое достаточно двух-трёх явных аргументов.

**Q6: Чем `void` отличается от «вернул `undefined`»?**  
`void` говорит вызывающему: не используй результат. Функция может не иметь `return` или иметь `return;` — для логгера и клика это норма. Если написал `: undefined`, обычно ждут явный `return undefined`. Не клади `void` на функцию, чей результат потом подставляют в выражение.

**Q7: Нужно ли писать `: string` у `paint`, если `return` уже строка?**  
Не обязательно: вывод из `return` сработает. Имеет смысл на публичной границе модуля (тема 14) или когда ветки разные и хочешь зафиксировать контракт. Для учебной `area` явный `: number` учит читать дверь функции.

**Q8: Где ставить необязательный параметр?**  
В конце списка: `area(w: number, h: number, unit?: string)`. Перед обязательным его не поставить. Значение по умолчанию `unit = "м²"` делает параметр необязательным и сразу даёт строку внутри. Это тот же `?`, что у поля объекта в теме 5, только у аргумента.

**Q9: Как типизировать колбэк `map`?**  
Элемент массива уже имеет тип (тема 4). Колбэк `(lesson: Lesson) => string` или дай вывести из тела. Не ставь `any`. Если массив `Lesson[]`, параметр часто выводится сам — проверь, что не расширил до `any[]`.

**Q10: Зачем в этом слое `(event: Event) => void`, если клик — Junior тема 18?**  
Чтобы не тащить `any` в обработчик и не врать компилятору. Если `event` не нужен — обёртка без параметра. Подробные DOM-типы — тема 11. Не копируй сигнатуры React: JSX в слое нет.

## Тема 8 — Сужение (narrowing)

→ Следующая тема: [9 — Простые дженерики и `Promise<T>`](section_4_reuse.md#тема-9--простые-дженерики-и-promiset)

### Теория с аналогией

**Аналогия: коридор сужается**

Как в 🔗 Junior теме 13, внутри блока видно меньше внешнего мира. Здесь наоборот: внутри `if` мир типа **уже**. Снаружи `id: string | number`, внутри `typeof id === "string"` — это строка.

```typescript
function labelValue(value: string | number): string {
  if (typeof value === "string") {
    return value.toUpperCase();
  }
  return String(value);
}

function titleOf(el: { textContent: string | null }): string {
  if (el.textContent === null) {
    return "";
  }
  return el.textContent;
}

function hasTitle(draft: object): void {
  if ("title" in draft) {
    console.log("есть ключ title");
  }
}
```

Рабочие проверки этого слоя: `typeof`, `=== null`, `=== undefined`, `Array.isArray`, `"поле" in obj`, проверка поля `if (draft.title)`.

Тегированное объединение с полем `kind` / `status` — тема 12. Не подменяй его `as` (тема 10).

### Где это в реальном коде

- JSON: сначала `unknown`, потом проверки (тема 10, затем 13).
- DOM: `if (!node) return` (тема 11).
- Ответ API: `if (typeof data.title !== "string") return`.

### Паттерны

❌ `value as string` чтобы замолчать  
✅ `typeof` / `null` / `in`  
Почему: `as` не проверяет runtime.

❌ Сужать вложенными `if` на пять этажей  
✅ Ранний `return`  
Почему: читается как Junior-поток (тема 8 Junior).

❌ Проверить `typeof` и забыть `return` в обеих ветках  
✅ Каждая ветка возвращает обещанный тип  
Почему: иначе функция не `string`.

### Вопросы

**Q1: Почему `typeof null` в JS — `"object"`, а для narrowing это ловушка?**  
Как в 🔗 Junior теме 7: `typeof null === "object"`. Ветка `typeof x === "object"` не отсекает `null`. Для пустоты пиши `=== null` или `== null` осознанно. Не учи «объект проверяю через typeof» без этой оговорки.

**Q2: Сужение работает только в `if`?**  
Ещё `switch`, тернарный оператор, иногда `&&`. Для курса достаточно `if` и early return. Главное — проверка должна быть в том же потоке, где потом используешь суженный тип. Вынеси проверку в другую функцию без предиката `x is T` (тема 10) — компилятор часто «забудет».

**Q3: После `return` в `if` ниже тип уже без этого варианта?**  
Да. Early return выкидывает ветку из дальнейшего анализа. Ниже остаётся то, что не попало в `if`. Это тот же приём, что в Junior теме 8, только типы следуют за потоком. Не дублируй проверку ниже «на всякий случай», если уже сузил.

**Q4: `!value` сужает?**  
Для `string | null` — да, но пустая строка тоже отсечётся: она ложна. Для `number | undefined` ноль ложноват — `if (!n)` выкинет законный `0`. Для объектов удобнее `=== null` / `=== undefined`. Не сужай числа через `!` без мысли.

**Q5: Нужен ли narrowing, если тип уже `string`?**  
Нет. Он нужен на union, `| null`, `| undefined`, `unknown` (тема 10). Лишний `typeof` на чистой строке — шум. Если `tsc` просит проверку — тип шире, чем ты думаешь: открой подсказку в IDE.

**Q6: Что даёт `"title" in draft`?**  
Проверку ключа в объекте: после `if` компилятор знает, что ключ есть (с оговорками прототипа — в слое достаточно «ключ на объекте»). Не путай с `draft.title != null`: поля может не быть в типе. Для произвольного `object` `in` — рабочий приём этого слоя.

**Q7: Чем `Array.isArray(x)` полезен на `string | string[]`?**  
После проверки `x` — массив, и можно `.map`. Без неё у union нет методов массива. `typeof x === "object"` здесь слабже: массив тоже объект, плюс ловушка `null`. Для массива бери `Array.isArray`.

**Q8: Почему `as string` — не сужение?**  
Утверждение `as` говорит компилятору «поверь», без проверки в runtime (тема 10). Сужение — реальный `if`. Если данные с сервера, `as` оставит опечатку до клика пользователя. В этой теме чини форму проверкой, не молчанием.

**Q9: Можно ли сузить union объектов по полю `kind: "ok" | "err"`?**  
Да, и это заготовка темы 12: после `if (s.kind === "ok")` доступны поля этого варианта. Пока достаточно понять идею. Не собирай `{ data, error }` с обоими полями сразу, если состояния взаимоисключающие.

**Q10: Связано ли сужение с Junior `if` / `typeof`?**  
Да. Ты уже писал эти проверки в Junior темах 4 и 8. TS не добавляет новый синтаксис потока — он *следит* за ним. Если проверка неубедительна для компилятора (`typeof null`), тип не сузится. Пиши проверки так, чтобы и движок, и `tsc` видели одно и то же.
