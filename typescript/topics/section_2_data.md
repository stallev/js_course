# Раздел 2 — Описываем данные

Как в 🔗 Junior разделе 2, путаница «думал, что число» ломает программы. Здесь ту же мысль записываем так, чтобы компилятор спорил с тобой, а не пользователь.

## Тема 3 — Примитивы и вывод типов

← Предыдущая тема: [2 — Запуск](section_1_setup.md#тема-2--запуск-tsx-tsc-tsconfig)  
→ Следующая тема: [4 — Объекты, массивы, `type`](#тема-4--объекты-массивы-type)

---

### Теория с аналогией

**Аналогия: ценник на полке и ценник «и так видно»**

`let age: number = 18` — ценник написан. `let age = 18` — продавец (компилятор) сам видит, что это число. Это **вывод типов** (inference).

```typescript
let title = "Курс"; // string
let year = 2026;    // number
let ready = true;   // boolean

title = "Junior";
// title = 1; // ошибка: number не string
```

Как в 🔗 Junior теме 2, `const` нельзя переприсвоить; тип всё равно есть: `const n = 1` это `1` (литерал) или как минимум число в выражениях.

**Когда аннотация нужна сразу**

- параметры функций (тема 6) — снаружи не из чего вывести;
- пустой массив: `const ids: number[] = []` иначе станет `never[]` и туда ничего не положишь.

### Где это в реальном коде

Счётчик кликов — `number`. Текст кнопки — `string`. Флаг «форма валидна» — `boolean`. Как Junior темы 5 и 18, только с подписью на границе функции.

### Паттерны

❌ `let x: string | number | boolean | null` «на всякий случай»  
✅ Один смысл — один тип; несколько смыслов — тема 5, осознанно  
Почему: широкий тип ничего не ловит.

❌ `let n: number = 1` везде  
✅ `let n = 1`, аннотация на параметре  
Почему: вывод уже знает.

❌ Менять тип той же переменной (`let x = 1; x = "a"`)  
✅ Две переменные или union, если правда оба варианта  
Почему: в JS так можно, в strict TS — нет, и это плюс.

### Вопросы

**Q1: Откуда TS знает тип `let n = 1`?**  
Из литерала `1`.

**Q2: Чем аннотация отличается от `typeof` в Junior?**  
`typeof` — в runtime. Аннотация — для компилятора, в запущенном JS её нет (тема 1).

**Q3: Почему пустой `const xs = []` неудобен?**  
Слишком узкий/пустой вывод. Напиши `number[]` или положи первый элемент.

**Q4: `const` и тип?**  
Значение не меняется; тип всё равно проверяется при использовании.

**Q5: Нужно ли писать `boolean` для `ready = true`?**  
Нет, если вывод очевиден.

### Практическое задание

Функция `describePrimitives`: залогируй строку, число и boolean; верни длину строки как `number`.

### Решение с инсайтом

```typescript
export function describePrimitives(): number {
  const title = "Курс";
  const year = 2026;
  const ready = true;
  console.log(title, year, ready);
  return title.length;
}
```

**Инсайт:** локальным значениям часто хватает вывода; контракт — на входе и выходе функции.

## Тема 4 — Объекты, массивы, `type`

← Предыдущая тема: [3 — Примитивы и вывод типов](#тема-3--примитивы-и-вывод-типов)  
→ Следующая тема: [5 — Union, optional, `null`](#тема-5--union-optional-null)

---

### Теория с аналогией

**Аналогия: анкета**

Как в 🔗 Junior теме 14, объект — поля. TS описывает **форму анкеты**: какие ключи и какие типы значений.

```typescript
type User = {
  name: string;
  age: number;
};

const anna: User = { name: "Анна", age: 20 };
// const bad: User = { name: "Анна" }; // нет age
```

`type` — имя для формы, чтобы не копировать фигурные скобки. Массив: `User[]` или `Array<User>` (дженерик `Array` — тема 8, пока достаточно `User[]`).

Как в 🔗 Junior теме 15, методы `map`/`filter` сохраняют тип элементов, если колбэк описан (тема 6).

Лишние поля при **прямой** записи в переменную типа `User` часто запрещены. Отдельная переменная без аннотации, которую потом передали — правила чуть мягче; в курсе пиши объект сразу как `User`.

### Где это в реальном коде

Список уроков: `{ id: number; title: string }[]`. Конфиг песочницы. Тело JSON после проверки (тема 9) тоже сводят к `type`.

### Паттерны

❌ Анонимные `{ name: string }` в пяти функциях  
✅ Одно имя `type User`  
Почему: правка возраста — в одном месте.

❌ `interface` и `type` спорить на первой неделе  
✅ В этом слое везде `type` для объектов  
Почему: одного инструмента хватает; `interface` встретится в Middle.

❌ `string[][][]` без нужды  
✅ Плоский массив объектов  
Почему: вложенность путает narrowing (тема 7).

### Вопросы

**Q1: `type` существует в runtime?**  
Нет. Стирается, как аннотация.

**Q2: Чем `User[]` отличается от `User`?**  
Массив анкет vs одна анкета.

**Q3: Можно ли поле-функция?**  
Да: `greet: (name: string) => string` — тема 6.

**Q4: Обязательны ли все поля?**  
Пока да. Необязательные — `?` в теме 5.

**Q5: Нужно ли копировать объект из-за типов?**  
Нет. Ссылка та же, что в 🔗 Junior теме 16. Тип не клонирует данные.

### Практическое задание

Опиши `type Lesson` с `id` и `title`. Функция `describeLesson(lesson: Lesson)` логирует строку `"id: title"`.

### Решение с инсайтом

```typescript
export type Lesson = {
  id: number;
  title: string;
};

export function describeLesson(lesson: Lesson): void {
  console.log(`${lesson.id}: ${lesson.title}`);
}
```

**Инсайт:** `type` — имя формы, не коробка в памяти.

## Тема 5 — Union, optional, `null`

← Предыдущая тема: [4 — Объекты, массивы, `type`](#тема-4--объекты-массивы-type)  
→ Следующая тема: [6 — Типы функций](section_3_functions.md#тема-6--типы-функций)

---

### Теория с аналогией

**Аналогия: вилка на дороге и пустая клетка анкеты**

**Union** `string | number` — значение одно, но вид один из двух (id с сервера иногда строка).

**Optional** `title?: string` — ключа может не быть (как «клетка не заполнена»). Это не то же, что `title: string | undefined` в деталях записи объекта, но в чтении часто рядом.

**`null` и `undefined`** — как 🔗 Junior тема 7. При `strict` нельзя положить `null` в `string` без `| null`. `querySelector` в теме 9 как раз `Element | null`.

```typescript
type Id = string | number;

function formatId(id: Id): string {
  return String(id);
}

type Draft = {
  title?: string;
};

type MaybeTitle = {
  title: string | null;
};
```

Пока не сузил union (тема 7), доступны только операции, общие для всех вариантов: для `string | number` нет `.toUpperCase()` без проверки.

### Где это в реальном коде

- `response.status` — число, текст ошибки — строка: не мешай в одну переменную без union.
- Необязательный email в форме.
- «Ещё не загрузили» — `data: User | null`.

### Паттерны

❌ `any` вместо union  
✅ Перечислить варианты `|`  
Почему: `any` выключает слой (тема 9).

❌ `string | number | boolean | null | undefined` на всё  
✅ Два-три смысла максимум  
Почему: иначе сужение нечитаемо.

❌ Игнорировать `null` у DOM  
✅ Проверка `if (!el) return`  
Почему: элемент могли не найти (🔗 Junior тема 17).

### Вопросы

**Q1: `?` и `| undefined` — одно и то же?**  
Похожи при чтении. При создании объекта `?` позволяет ключ не писать.

**Q2: Почему нет `.length` у `string | number`?**  
У числа нет `.length`. Сначала сузь (тема 7).

**Q3: Зачем `| null`, если есть optional?**  
`null` — явное «пусто». Нет ключа — другое. В DOM чаще `| null`.

**Q4: `undefined` из Junior `let x` без значения?**  
Да, тип будет `undefined`, пока не аннотируешь иначе.

**Q5: Union в массиве?**  
`(string | number)[]` — каждый элемент — строка или число. Не путать с кортежем `[string, number]` (в этом слое не ядро).

### Практическое задание

`formatId(id: string | number): string` — всегда строка для лога. `labelDraft(d: { title?: string })` — если нет title, лог `"без названия"`.

### Решение с инсайтом

```typescript
export function formatId(id: string | number): string {
  return String(id);
}

export function labelDraft(d: { title?: string }): void {
  console.log(d.title ?? "без названия");
}
```

**Инсайт:** `|` — честный список вариантов; `?` — поле может не прийти. Дальше компилятор заставит сузить.
