# Раздел 1 — Слой поверх JS

Junior уже научил запускать `.js`, класть значения в `let`/`const` и собирать шаги в функции. TypeScript не новый язык с другой логикой `if` и массивов: это **тот же JavaScript плюс заметки о форме данных**, которые читает компилятор *до* запуска.

Этот раздел отвечает на два бытовых вопроса: *зачем* эти заметки и *какой командой* файл `.ts` проверить и выполнить.

### Теория с аналогией

**Аналогия: проверка орфографии до отправки письма**

JavaScript выполняет код и падает, когда уже «письмо ушло»: функция ждала строку, а пришло число — ошибка в консоли у пользователя. TypeScript — проверка черновика: редактор и `tsc` подчёркивают несовпадение *пока файл ещё у тебя*.

Как в 🔗 Junior теме 4, у значения есть тип (`typeof`). TS фиксирует ожидаемый тип **в тексте программы**, а не только в голове.

```
  файл.ts          tsc / IDE              движок JS
  (JS + типы)  →   красные ошибки     →   выполняется уже без типов
                   или «можно запускать»
```

**Типы стираются.** После проверки в файле не остаётся `string` и `number`. Браузер и Node видят обычный JS — как в 🔗 Junior теме 1.

```typescript
function greet(name: string): string {
  return "Привет, " + name;
}

greet("Анна");
// greet(42); // tsc: number не string
```

После стирания останется примерно:

```javascript
function greet(name) {
  return "Привет, " + name;
}
```

TS **не** защищает от всего: деление на ноль, сеть, опечатка в данных с сервера — это runtime, как раньше. Он ловит то, что можно сказать по форме: «эта функция ест строку».

### Где это в реальном коде

- Параметр функции формы: `value: string` из `input.value` (🔗 Junior тема 19).
- Ответ `fetch`: сначала `unknown` или свой `type`, не «любой объект» (тема 9 этого слоя; 🔗 Junior тема 23).
- Экспорт модуля: снаружи видно и JS-имя, и тип (🔗 Junior тема 25).

### Вопросы

**Q1: TypeScript — другой язык или слой над JS?**  
Слой: синтаксис JS плюс аннотации. Движок выполняет JS после стирания типов.

**Q2: Когда ошибка TS проявляется — при клике или раньше?**  
Обычно в редакторе и при `tsc`, до запуска. Если обойти проверку (`any`, `as`), ошибка может вернуться в runtime.

**Q3: Защищает ли TS от пустого массива и сетевой ошибки?**  
Нет. Он описывает форму. Пустой массив типа `number[]` законен. Сеть — 🔗 Junior тема 23.

**Q4: Почему `greet(42)` красное, а в чистом JS «работает» до странной строки?**  
JS сложит `"Привет, " + 42`. TS считает это нарушением контракта `string`.

**Q5: Нужен ли TS, если я один и файлов мало?**  
Не обязателен. Имеет смысл, когда функции вызывают друг друга и легко перепутать аргумент. Этот слой — привычка до Middle.

### Теория с аналогией

**Аналогия: черновик, корректор и сцена**

- **`tsc`** — корректор: читает `.ts`, ругается на типы, по желанию пишет `.js`.
- **`npx tsx файл.ts`** — сцена: проверил (через тот же мир TS) и сразу выполнил, как `node файл.js` в 🔗 Junior теме 1.
- **`tsconfig.json`** — правила корректора: `strict` включает полезные проверки, в том числе пустые значения (тема 5).

Минимальный смысл опций для этого слоя:

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ES2020",
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["topics/**/*.ts"]
}
```

`strict: true` — пакет строгих правил. Без него часть ошибок «молчаливая». В sandbox курса этот флаг уже включён.

**Две привычки**

```bash
# из корня js_course: выполнить упражнение
npx tsx typescript/sandbox/js_sandbox/topics/topic_2/exercises.ts

# только проверка типов всего sandbox
npx tsc -p typescript/sandbox/js_sandbox/tsconfig.json --noEmit
```

Браузер не читает `.ts`. Для раннера: `npm run bridge:watch` пишет рядом `exercises.js`, страница импортирует его — как Junior Live Server, только исходник `.ts`.

### Где это в реальном коде

- Локально: `tsx` на скрипт без сборки сайта.
- CI: `tsc --noEmit`, чтобы не влить красный файл.
- Фронт: Vite/Next сами зовут компилятор; в этом слое достаточно `tsc` + Live Server.

### Паттерны

❌ Открывать `.ts` как `file://` в браузере  
✅ Live Server после `bridge:watch`, либо только `tsx`  
Почему: нет движка TS в обычной вкладке.

❌ Выключать `strict`, чтобы «прошло»  
✅ Починить тип (темы 5, 7, 9)  
Почему: иначе слой бесполезен.

❌ Держать два разных `tsconfig` «на глаз» без `include`  
✅ Один конфиг на sandbox, как в репозитории  
Почему: иначе `tsc` не видит файлы.

### Вопросы

**Q1: Чем `tsx` отличается от `node файл.js`?**  
`tsx` понимает TypeScript и ESM `.ts`. `node` ждёт JS (или настройку, которой в Junior не было).

**Q2: Что делает `--noEmit`?**  
Проверяет типы и **не** пишет `.js`. Удобно в CI.

**Q3: Зачем `target`?**  
В какой диалект JS скомпилировать (`const`, стрелки). `ES2020` достаточно для курса.

**Q4: Нужен ли `npm install`?**  
Да, один раз в корне: в `package.json` уже есть `typescript`. `tsx` подтянется через `npx`.

**Q5: Если `tsc` красный, а `tsx` всё равно бежит?**  
Иногда инструменты расходятся. Ориентир слоя — красное в `tsc -p ... --noEmit` чинить, не игнорировать.
