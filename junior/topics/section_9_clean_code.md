### Теория с аналогией

**Аналогия: подписи на ящиках и короткие рецепты**

Ящик «шт» через месяц — загадка. Ящик «количествоВКорзине» — нет. Рецепт на три страницы без названий шагов невозможно повторить. Как мы видели в 🔗 теме 11, имя функции — глагол или ответ. Как в 🔗 теме 3, комментарий объясняет *зачем*, не «присваиваем n».

**Имена**

```javascript
// слабо
let d;
let flag;
function data(a) {}

// сильнее
let daysLeft;
let isReady;
function totalPrice(price, count) {}
```

- Переменная — существительное: `user`, `price`, `titleInput`.
- Булево — вопрос: `isReady`, `hasTicket`, `canSubmit` (🔗 тема 5).
- Функция — действие или расчёт: `add`, `loadTodo`, `describeAge`.
- Константа-лимит: `MAX_RETRIES`, `TAX` (тема 2).

Не транслит `polzovatel`. Не `data2`, `temp`, `x1`, если это не индекс цикла `i` в коротком `for`.

Одна буква `i` / `n` допустима в крошечном цикле на 3 строки (🔗 тема 9). В функции на пол-экрана — уже `index` / `attempt`.

**Маленькие функции**

Одна функция — одна мысль. Если в голове «и ещё, и ещё» — режь.

```javascript
// слабо: и разбор, и проверка, и текст на страницу
function go(raw) {
  const age = Number(raw);
  if (Number.isNaN(age)) {
    out.textContent = "не число";
    return;
  }
  out.textContent = age >= 18 ? "можно" : "рано";
}

// сильнее
function parseAge(raw) {
  const age = Number(raw);
  if (raw === "" || Number.isNaN(age)) {
    return null;
  }
  return age;
}

function accessLabel(age) {
  if (age < 18) {
    return "рано";
  }
  return "можно";
}
```

`go` тогда только: прочитал поле → `parseAge` → если `null`, сообщение → иначе `accessLabel` → `textContent`. Каждую функцию можно проверить отдельно `console.log` без DOM.

Повторил один и тот же `Number` + `isNaN` в трёх местах — вынеси. Это не «паттерн DRY из middle», а жалость к себе.

**Магические числа**

```javascript
if (age >= 18) {
```

Восемнадцать — законный порог, имя не обязательно. А `if (ms > 86400000)` — уже `const MS_IN_DAY = 86400000`.

**Схема**

```
  длинный обработчик клика
       │ разрезать
       ▼
  parseXxx()     →  данные
  decideXxx()    →  строка / булево
  renderXxx()    →  DOM
```

Модуль (тема 25) кладёт `parse`/`decide` в `age.js`, обработчик остаётся тонким.

### Паттерны

**1. Имя вместо комментария «что делает строка»**

Так лучше не делать: `let n = 0; // счётчик кликов`.

Так лучше: `let clickCount = 0`.

Почему: комментарий врать начнёт первым. Имя компилируется вместе с кодом.

**2. Функция помещается в кадр головы**

Так лучше не делать: 80 строк с пятью уровнями `if` в одном `onSubmit`.

Так лучше: куски по 5–20 строк с понятным `return`.

Почему: ошибка локализуется. Тест в голове: «что входит, что выходит».

**3. Не переименовывай в однобуквенное «чтобы быстрее набрать»**

Так лучше не делать: `const u = users.filter((x) => x.a > 18)`.

Так лучше: `const adults = users.filter((user) => user.age > 18)`.

Почему: набор экономит секунды, чтение стоит часы. Исключение — `i` в коротком `for`.

### Вопросы

**Q1: Зачем хорошие имена, если «и так понятно из контекста»?**

Контекст выветривается. Через неделю контекст — другой файл. Имя — единственный комментарий, который ты точно прочитаешь, открыв строку. Junior-баг «не тот `data`» почти всегда безымянная каша.

**Q2: Насколько маленькая функция — достаточно маленькая?**

Если не можешь сказать вслух одним предложением, что она делает — режь. Не цель «все функции по три строки». Цель — одна ответственность: разобрать **или** нарисовать, не оба сразу вперемешку с сетью.

**Q3: Это уже SOLID / KISS?**

Близко к здравому смыслу KISS, без экзамена по аббревиатурам. SOLID и каталог паттернов — middle, раздел про архитектуру. Здесь достаточно: ясное имя, короткий шаг, без копипасты проверки `NaN`.

**Q4: Когда комментарий всё же нужен?**

Когда имя не вмещает правило бизнеса: «18 — порог по ТЗ заказчика от 2024». Не дублируй код. Тема 3: пиши *зачем*. Не комментируй каждую строку `return`.

**Q5: Что делать после этого курса?**

Повтори задания разделов 1–8 вслух: запуск, типы, `===`, DOM, `await fetch`, модуль. Потом слой TypeScript в этом репозитории (когда появится каталог). Затем middle — Event Loop вглубь, `this`, прототипы, React. Не прыгай в middle, пока не запускаешь DOM и `fetch` без шпаргалки каждую строку.

### Практическое задание

Файл `clean.js` (можно без DOM).

Дана каша (перепиши, не запускай как образец стиля):

```javascript
function f(a) {
  let x = Number(a);
  if (a == "" || x != x) return "нет";
  if (x >= 18) return "ok";
  return "no";
}
```

Сделай:

1. Имена: сырой ввод, возраст, подпись.
2. Строгое сравнение, без `==` и без трюка `x != x` для NaN — используй `Number.isNaN` (🔗 темы 5–7).
3. Две функции: разбор в число или `null`, отдельная подпись по возрасту.
4. Вызови с `"20"`, `""`, `"привет"` и выведи результаты.

### Решение с инсайтом

```javascript
function parseAge(raw) {
  if (raw === "") {
    return null;
  }
  const age = Number(raw);
  if (Number.isNaN(age)) {
    return null;
  }
  return age;
}

function accessLabel(age) {
  if (age >= 18) {
    return "можно";
  }
  return "рано";
}

function describeAge(raw) {
  const age = parseAge(raw);
  if (age === null) {
    return "нет";
  }
  return accessLabel(age);
}

console.log(describeAge("20"));
console.log(describeAge(""));
console.log(describeAge("привет"));
```

**Инсайт:** имя говорит, что лежит в коробке. Маленькая функция говорит, какой шаг выполняется. Стиль — часть языка, не украшение после «настоящего кода».
