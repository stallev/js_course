# Раздел 6 — DOM и события

До сих пор код жил в консоли и в `node` (🔗 тема 1). Страница — дерево тегов. Браузер строит из HTML **DOM**: объекты-узлы, как карточки из 🔗 темы 14, только их создал не ты, а движок страницы.

В Node нет `document`. Примеры этого раздела открывай как HTML + `.js` (скрипт в конце `body`, Live Server или двойной щелчок). Консоль — по-прежнему DevTools.

### Теория с аналогией

**Аналогия: план здания**

HTML — чертёж. DOM — уже построенные комнаты: в каждую можно зайти, переклеить табличку на двери, не переписывая весь чертёж с нуля. JavaScript ходит по комнатам с бейджиком `id` или классом.

Как мы видели в теме 1, скрипт в конце `body` видит уже нарисованные теги. Если скрипт в `<head>` без ожидания загрузки, `querySelector` часто вернёт `null`: комнаты ещё нет.

**Дерево**

```
  document
    └── html
          ├── head
          └── body
                ├── h1#title
                └── p.status
```

`document` — корень. Поиск почти всегда от него (или от уже найденного узла).

**Найти один узел**

```html
<h1 id="title">Курс</h1>
<p class="status">черновик</p>
```

```javascript
const title = document.querySelector("#title");
const status = document.querySelector(".status");
const byId = document.getElementById("title"); // без #

console.log(title); // элемент или null
```

- `#id` — как в CSS, уникальный якорь.
- `.class` — первый подходящий. Все сразу: `querySelectorAll(".item")` — список, по нему `for...of` (🔗 темы 9 и 15).
- Не нашли — `null` (🔗 тема 7), не пустая строка. Чтение `.textContent` у `null` — падение.

```javascript
const el = document.querySelector("#nope");
if (el === null) {
  console.log("нет узла");
} else {
  console.log(el.textContent);
}
```

**Текст и HTML**

```javascript
title.textContent = "JavaScript Junior"; // текст, безопаснее для чужих строк
// title.innerHTML = "<em>курс</em>";    // вставляет разметку
```

`textContent` — символы как текст. `innerHTML` — браузер разберёт теги. Если вставишь строку из поля ввода через `innerHTML`, можно подложить чужой `<script>`-подобный HTML. Правило Junior: **данные пользователя — в `textContent`**.

**Атрибуты и классы**

```javascript
const img = document.querySelector("img");
img.getAttribute("alt");
img.setAttribute("alt", "кот");
img.src = "cat.jpg";          // многие атрибуты есть и как поля

status.classList.add("ok");
status.classList.remove("ok");
status.classList.toggle("hidden");
```

Поля вроде `.src`, `.href`, `.id` — удобные ярлыки. Произвольный атрибут `data-id` — через `getAttribute` / `dataset` (достаточно `getAttribute("data-id")`).

**Схема**

```
  HTML (чертёж)  →  браузер строит DOM  →  querySelector находит узел
                                              │
                                              ├── textContent
                                              ├── атрибуты
                                              └── classList
```

---

### Где это в реальном коде

- Счётчик на странице: нашли `#count`, пишем `textContent`.
- Подпись к картинке: `alt` через атрибут.
- Список: `querySelectorAll("li")`, цикл, каждому своё.
- Виджет «ошибка»: `classList.add("error")` вместо ручной сборки стилей в JS.

---

### Паттерны

**1. Скрипт после разметки, которую ищешь**

Так лучше не делать: `<script src="app.js">` в `<head>` и сразу `querySelector("#app")`.

Так лучше: скрипт в конце `body` или искать после того, как узел точно в HTML.

Почему: DOM ещё не построил `#app` → `null` → падение на `.textContent`.

**2. Проверяй `null`**

Так лучше не делать: цепочка без проверки, опечатка в `id`.

Так лучше: `if (el === null) { console.log("нет #title"); return; }`.

Почему: опечатка в селекторе — самая частая «DOM сломался», хотя сломалось имя.

**3. Чужой текст — `textContent`**

Так лучше не делать: `el.innerHTML = input.value`.

Так лучше: `el.textContent = input.value`.

Почему: пользователь не должен стать источником разметки. `innerHTML` — когда доверяешь шаблону, который написал сам.

---

### Вопросы

**Q1: Чем DOM отличается от файла HTML?**

HTML — текст на диске. DOM — живые объекты в памяти браузера после разбора. JS меняет DOM; чтобы увидеть исходный файл, смотри «View Source». DevTools показывает текущее дерево, уже с правками скрипта.

**Q2: Что вернёт `querySelector`, если узла нет?**

`null`. Не пустую коллекцию и не `undefined` в типичном случае поиска одного узла. Дальше любое `.textContent` без проверки — ошибка. Это та же пустота, что в теме 7, только источник — страница, не переменная.

**Q3: Чем `textContent` отличается от `innerHTML`?**

`textContent` ставит и читает текст как символы: `<` останется знаком «меньше». `innerHTML` просит браузер разобрать строку как HTML. Для подписей и имён — первое. Для вставки готовой вёрстки из своего кода — второе, осторожно.

**Q4: Зачем `classList`, если есть `className`?**

`className` — одна строка всех классов, легко затереть чужие. `classList.add` / `remove` / `toggle` меняют один класс, остальные не трогают. Для «включить состояние» на узле — `classList`.

**Q5: Почему этот раздел нельзя прогнать через `node app.js`?**

У Node нет страницы и нет `document`. Тот же язык, другая кухня (тема 1). DOM-примеры — только браузер.

2. Прочитай `title.textContent` в консоль.
3. Запиши в `#out` строку `"узел найден"` через `textContent`.
4. Добавь абзацу класс `ready` через `classList`.

Открой HTML в браузере, проверь страницу и Console.

### Решение с инсайтом

```html
<!DOCTYPE html>
<html>
  <body>
    <h1 id="title">Курс</h1>
    <p id="out"></p>
    <script src="dom.js"></script>
  </body>
</html>
```

```javascript
const title = document.querySelector("#title");

if (title === null || out === null) {
  console.log("нет узла");
} else {
  console.log(title.textContent);
  out.textContent = "узел найден";
  out.classList.add("ready");
}
```

**Инсайт:** DOM — дерево объектов страницы. Сначала найди узел и проверь, что это не `null`, потом меняй текст и классы.

### Теория с аналогией

**Аналогия: звонок на ресепшн**

Кнопка не вызывает твой код сама по себе. Браузер замечает жест (клик) и **звонит** на функцию, которую ты заранее оставил на ресепшн: «если клик по этой кнопке — выполни это».

Как мы видели в 🔗 теме 11, функция — набор шагов. Здесь ты её **не вызываешь сразу**: передаёшь как значение в `addEventListener` (коробка с функцией, тема 12). Браузер вызовет позже, когда случится событие.

```html
<button type="button" id="go">Жми</button>
<p id="out">ещё нет</p>
```

```javascript
const go = document.querySelector("#go");
const out = document.querySelector("#out");

function onGoClick() {
  out.textContent = "нажали";
}

go.addEventListener("click", onGoClick);
```

Порядок: найти узлы (тема 17) → объявить обработчик → подписаться. Имя события — строка `"click"`, `"input"`, `"submit"` (тема 19).

**Объект события**

Браузер передаёт в обработчик карточку события (🔗 тема 14):

```javascript
function onGoClick(event) {
  console.log(event.type);   // "click"
  console.log(event.target); // узел, по которому кликнули
  out.textContent = "нажали";
}
```

Параметр часто называют `event` или `e`. Пока достаточно `type` и `target`.

**`preventDefault`**

У некоторых жестов есть действие браузера по умолчанию: клик по ссылке — переход, отправка формы — перезагрузка. `event.preventDefault()` говорит «не делай стандартное, я сам». На обычной `type="button"` клик можно без этого. На форме — почти всегда нужно (тема 19).

**Несколько слушателей и снятие**

```javascript
go.addEventListener("click", onGoClick);
// go.removeEventListener("click", onGoClick); // та же функция, не анонимная
```

Снять можно только ту же ссылку на функцию (тема 16: тот же адрес). Анонимную `() => {}` снять потом не выйдет — не сохранишь адрес.

**Схема**

```
  жест пользователя
        │
        ▼
  браузер: есть слушатели на этом узле?
        │ да
        ▼
  вызов твоей функции(event)
```

Всплытие (клик на внутреннем узле всплывает к родителям) Junior может не зубрить. Знай: слушатель на родителе тоже может сработать. Для курса вешай слушатель на конкретную кнопку.

Атрибут HTML `onclick="..."` не используй как основной способ: логика смешивается с вёрсткой, сложнее снять и тестировать.

---

### Где это в реальном коде

- Кнопка «добавить в корзину»: `click` → меняешь `textContent` счётчика.
- Переключатель темы: `click` → `classList.toggle("dark")` на `body`.
- Поле поиска (тема 19): `input` — на каждую букву.
- Ссылка, которую обрабатываешь сам: `click` + `preventDefault`.

---

### Паттерны

**1. `addEventListener`, не `onclick` в HTML**

Так лучше не делать: `<button onclick="doStuff()">`.

Так лучше: `button.addEventListener("click", doStuff)`.

Почему: JS в одном файле, HTML не знает имён функций. Легче искать и не плодить глобальные `function` только ради атрибута.

**2. Проверяй, что узел найден, до подписки**

Так лучше не делать: `null.addEventListener` после опечатки в `id`.

Так лучше: как в теме 17, `if (go === null) return;`.

Почему: ошибка будет «addEventListener of null», хотя проблема — селектор.

**3. Обработчик короткий: нашёл данные → изменил DOM**

Так лучше не делать: в одном слушателе и поиск всех узлов мира, и расчёт на 80 строк без имён.

Так лучше: слушатель вызывает понятную функцию `updateLabel()` (темы 11 и 26).

Почему: отладка «что случилось по клику» занимает одну мысль.

---

### Вопросы

**Q1: Кто вызывает обработчик?**

Браузер, когда происходит событие. Ты только регистрируешь функцию. Если клика не было, тело не выполнялось — как объявление без вызова в теме 11, только вызов делает среда, не твоя строка `onGoClick()`.

**Q2: Чем `addEventListener` отличается от свойства `button.onclick = ...`?**

Свойство `onclick` держит **одну** функцию: второе присваивание затрёт первое. `addEventListener` позволяет несколько слушателей на одно событие. Снятие через `removeEventListener` требует ту же функцию. Для Junior бери `addEventListener` всегда.

**Q3: Что такое `event.target`?**

Узел, на котором событие *возникло* (кликнутый элемент). Иногда это вложенный `span` внутри кнопки. Для «какая кнопка» часто берут элемент, на который вешали слушатель (`go`), а не только `target`. Пока не путай: `target` — источник жеста.

**Q4: Зачем `type="button"` у кнопки в форме?**

Кнопка внутри `<form>` по умолчанию часто `submit` — отправит форму и перезагрузит страницу. `type="button"` — просто кнопка. Если нужен submit — тема 19 и `preventDefault`.

**Q5: Почему стрелка в `addEventListener` удобна и чем мешает?**

Удобна: короткий колбэк на месте. Мешает: не снимешь слушатель, если не сохранил ту же стрелку в `const`. Для учебной кнопки «на всю жизнь страницы» анонимность ок. Если будешь снимать — `const onGoClick = () => { ... }` и передай имя.

---

### Практическое задание

`click.html` + `click.js`. Кнопка `#go`, абзац `#out` с текстом `"0"`.

1. Найди узлы, проверь `null`.
2. `let clicks = 0`.
3. По клику увеличь счётчик и запиши его в `#out` через `textContent`.
4. В обработчике выведи в консоль `event.type`.

---

### Решение с инсайтом

```javascript
const go = document.querySelector("#go");
const out = document.querySelector("#out");

if (go === null || out === null) {
  console.log("нет узла");
} else {
  let clicks = 0;

  function onGoClick(event) {
    console.log(event.type);
    clicks = clicks + 1;
    out.textContent = String(clicks);
  }

  go.addEventListener("click", onGoClick);
}
```

`clicks` снаружи обработчика виден внутри (🔗 тема 13). Это нормально для счётчика на странице.

**Инсайт:** событие — звонок браузера в твою функцию. Подписка (`addEventListener`) и вызов — разные моменты.

## Тема 19 — Формы и ввод

← Предыдущая тема: [18 — События и обработчики](#тема-18--события-и-обработчики)  
→ Следующая тема: [20 — Callbacks](section_7_async.md#тема-20--callbacks-settimeout-и-события)

---

### Теория с аналогией

**Аналогия: анкета на стойке**

Поля — клеточки анкеты. Кнопка «отправить» — «отдать листок». Браузер по умолчанию уносит листок на сервер и **перезагружает** страницу. В учебном JS мы часто хотим прочитать клеточки сами и показать результат на месте: остановить унос — `preventDefault`, прочитать `.value`.

Как мы видели в 🔗 теме 5, значение поля — **строка**, даже если набрали `18`. Перед арифметикой — `Number`. Пустое поле — `""`, не `null` (🔗 тема 7).

```html
<form id="age-form">
  <input id="age" name="age" type="text" />
  <button type="submit">Ок</button>
</form>
<p id="out"></p>
```

```javascript
const form = document.querySelector("#age-form");
const ageInput = document.querySelector("#age");
const out = document.querySelector("#out");

form.addEventListener("submit", (event) => {
  event.preventDefault();

  const raw = ageInput.value;
  const age = Number(raw);

  if (raw === "") {
    out.textContent = "введите возраст";
    return;
  }

  if (Number.isNaN(age)) {
    out.textContent = "это не число";
    return;
  }

  out.textContent = age >= 18 ? "можно" : "рано";
});
```

Слушай **`submit` на форме**, не только клик по кнопке: Enter в поле тоже отправит форму.

**`input` — на каждое изменение**

```javascript
ageInput.addEventListener("input", () => {
  console.log(ageInput.value);
});
```

Для «живой» подписи. Для итогового решения обычно достаточно `submit`.

**Чекбокс**

Не `.value` как главный факт, а `.checked` — булево:

```javascript
const agree = document.querySelector("#agree");
console.log(agree.checked); // true / false
```

**Схема**

```
  submit
    → preventDefault (остаёмся на странице)
    → прочитать value (строка)
    → проверить пусто / Number / if
    → записать textContent результата
```

`try` / `catch` (🔗 тема 10) здесь не первый инструмент: пустая строка и `NaN` — ожидаемые ветки `if`, не исключения. `JSON.parse` поля — уже `try`.

---

### Где это в реальном коде

- Логин на учебной странице: два `input`, `submit`, проверка непустых строк.
- Калькулятор: два числа из полей, `Number`, сумма в абзац.
- Подписка: чекбокс «согласен» + `if (agree.checked === false)`.
- Позже `fetch` (🔗 тема 23): те же `value`, только отправишь на сервер сам.

---

### Паттерны

**1. `submit` + `preventDefault`**

Так лучше не делать: считать клик по кнопке и забывать Enter; или не вызывать `preventDefault` и удивляться, что страница мигнула и счётчик сбросился.

Так лучше: один слушатель `submit` на `<form>`.

Почему: перезагрузка убивает переменные в памяти. Кажется, что «JS не работает».

**2. Строка с поля → явное число**

Так лучше не делать: `ageInput.value + 1` и ждать 19.

Так лучше: `Number(raw)` и проверка `Number.isNaN` (темы 5–6).

Почему: `value` всегда текст. Склеивание — тема 5.

**3. Сообщения пользователю — на странице, не только в console**

Так лучше не делать: ошибка только в DevTools.

Так лучше: `out.textContent = "введите возраст"`.

Почему: пользователь консоль не открывает. Console — для тебя.

---

### Вопросы

**Q1: Почему после отправки формы «всё сбросилось»?**

Браузер выполнил действие по умолчанию: запрос и новая загрузка документа. Память скрипта с нуля. `preventDefault` в `submit` оставляет тебя на той же странице. Проверь, что слушатель на форме, а не только мечта о клике.

**Q2: Чем `value` отличается от `textContent`?**

`value` — содержимое поля ввода (то, что набрал человек). `textContent` — текст обычного узла (`p`, `h1`). У `input` для чтения ввода бери `value`. Писать ответ в абзац — `textContent`.

**Q3: Пустое поле — это `null`?**

Нет, это `""`. Проверка `=== ""` или `raw.trim() === ""`, если боишься пробелов (`trim` обрезает края). `null` поле само не станет, пока ты не заведёшь отдельную переменную.

**Q4: Когда `try` / `catch` на форме?**

Когда шаг реально бросает: кривой JSON в текстовом поле. «Не число» после `Number` — `NaN` и `if`, не исключение. Не оборачивай весь `submit` пустым `catch`.

**Q5: Зачем `name` у `input`, если есть `id`?**

`id` — поиск в DOM (`#age`). `name` — имя поля при *настоящей* отправке на сервер и в `FormData`. Для учебного чтения через `querySelector` хватает `id`. Оба иметь — нормально: `id` для JS, `name` для смысла поля.

### Практическое задание

`form.html` + `form.js`. Форма с полем `#title` (текст) и кнопкой submit, абзац `#out`.

1. На `submit` вызови `preventDefault`.
2. Если поле пустое — напиши в `#out` `"пусто"`.
3. Иначе запиши в `#out` текст `"Тема: "` плюс значение поля (`textContent`, не `innerHTML`).
4. Проверь отправку и кнопкой, и клавишей Enter в поле.

---

### Решение с инсайтом

```javascript
const form = document.querySelector("#topic-form");
const titleInput = document.querySelector("#title");
const out = document.querySelector("#out");

if (form === null || titleInput === null || out === null) {
  console.log("нет узла");
} else {
  form.addEventListener("submit", (event) => {
    event.preventDefault();
    const raw = titleInput.value;

    if (raw === "") {
      out.textContent = "пусто";
      return;
    }

    out.textContent = "Тема: " + raw;
  });
}
```

**Инсайт:** ввод с формы — строки. Сначала останови перезагрузку, потом читай `value`, потом решай `if`. На страницу пиши через `textContent`.
