# Раздел 4 — Функции

`if` и циклы (🔗 темы 8–9) уже умеют выбирать и повторять. Если один и тот же набор шагов нужен в трёх местах файла, копипаста разъедется. **Функция** — имя для набора шагов: вызвал, передал значения, получил результат.

В этом разделе нет `this`, каррирования и генераторов — это middle. Здесь: объявить, вызвать, вернуть, понять, какие переменные снаружи видны внутри.

## Тема 11 — Объявление, параметры, `return`

← Предыдущая тема: [10 — `try` / `catch`](section_3_control_flow.md#тема-10--try--catch)  
→ Следующая тема: [12 — Стрелочные функции](#тема-12--стрелочные-функции)

---

### Теория с аналогией

**Аналогия: рецепт с названием**

«Омлет» — не яйца на столе, а *инструкция*: возьми яйца (входы), сделай шаги, получи блюдо (результат). Пока рецепт не вызвали, на плите ничего нет. Как мы видели в 🔗 теме 1, файл выполняется сверху вниз — **объявление** функции только вешает табличку; **вызов** `имя()` запускает шаги.

```javascript
function greet(name) {
  console.log("Привет, " + name);
}

greet("Анна"); // Привет, Анна
greet("Павел");
```

- `function greet` — объявление, имя `greet`.
- `(name)` — **параметр**: коробка внутри функции (как `let`, 🔗 тема 2). На каждом вызове в неё кладут своё значение.
- `greet("Анна")` — **вызов**. `"Анна"` — **аргумент**, то что кладём в параметр.
- Фигурные `{ }` — тело, набор инструкций (🔗 тема 3).

**`return` — отдать результат наружу**

`console.log` печатает, но не кладёт значение в коробку снаружи. `return` — «вот ответ, закончили»:

```javascript
function add(a, b) {
  return a + b;
}

const sum = add(2, 3);
console.log(sum); // 5
```

`add(2, 3)` — **выражение**: у вызова есть результат. Его можно положить в `const`, передать в другой `console.log`, использовать в `if`.

После `return` тело не продолжается:

```javascript
function label(age) {
  if (age < 18) {
    return "рано";
  }
  return "можно";
}

console.log(label(15)); // рано
console.log(label(20)); // можно
```

Ветвление из 🔗 темы 8 живёт внутри функции нормально. Два `return` — два выхода, не «магия».

**Нет `return` — результат `undefined`**

```javascript
function logSum(a, b) {
  console.log(a + b);
}

const x = logSum(2, 3); // печатает 5
console.log(x);         // undefined
```

Как в 🔗 теме 7: «не положили ответ». Печать ≠ возврат. Если снаружи нужно число — `return`.

**Не передали аргумент**

```javascript
function greet(name) {
  console.log(name);
}

greet(); // undefined — параметр есть, значение не клали
```

Проверка: `if (name === undefined)` или значение по умолчанию:

```javascript
function greet(name = "гость") {
  console.log("Привет, " + name);
}

greet();        // Привет, гость
greet("Анна");  // Привет, Анна
```

**Схема**

```
  объявление:   function add(a, b) { return a + b; }
                              │              └── отдать наружу
                           коробки на время вызова

  вызов:        add(2, 3)  →  кладём 2 и 3  →  выражение, результат 5
```

Объявление `function имя()` можно вызывать строкой выше в том же файле (движок заранее знает имя). Привычка Junior: **сначала объявил, ниже вызвал** — так проще читать, без споров про подъём объявлений.

---

### Где это в реальном коде

- Скрипт ценника: `function total(price, count) { return price * count; }` — одна формула, много вызовов.
- Node CLI: `function printHelp() { console.log("..."); }` — не копировать текст подсказки.
- Разбор входа: `function toAge(raw) { return Number(raw); }` плюс `if` / `throw` из тем 8 и 10.
- Позже обработчик кнопки (🔗 тема 18) — тоже функция, её вызовет браузер.

---

### Паттерны

**1. Считай `return`, показывай снаружи**

Так лучше не делать: внутри функции только `console.log` суммы, а снаружи ждать число в `const`.

Так лучше: `return` числа, `console.log` в месте, где решаешь «показать человеку».

Почему: функцию можно вызвать в расчёте, в `if`, в тесте. Лог прибит к консоли и мешает переиспользовать.

**2. Имя — глагол или ответ на «что получим»**

Так лучше не делать: `function data(a, b)`.

Так лучше: `function add(a, b)`, `function isAdult(age)`.

Почему: вызов `add(2, 3)` читается вслух. Имена — 🔗 тема 26, здесь достаточно глагола.

**3. Параметры — входы, не глобальный черновик**

Так лучше не делать: функция без параметров читает и меняет `let` с самого верха файла «потому что так короче».

Так лучше: передать нужное аргументами, вернуть результат.

Почему: иначе не видно, от чего зависит ответ. Случайная правка верхней переменной ломает все вызовы. Исключение — тема 13, когда снаружи *намеренно* читают настройку.

---

### Вопросы

**Q1: Чем объявление отличается от вызова?**

Объявление описывает шаги и вешает имя. Пока нет `имя()`, тело не выполняется (кроме разбора самого объявления). Вызов — момент готовки: подставляются аргументы, идут инструкции, срабатывает `return` или конец тела. Можно объявить один раз и вызвать десять.

**Q2: Чем параметр отличается от аргумента?**

Параметр — имя коробки *внутри* функции, в списке `(name, age)`. Аргумент — значение *на вызове*: `greet("Анна")`. На разных вызовах в одну и ту же коробку `name` кладут разное. Снаружи имени `name` нет, если ты его не объявлял отдельно.

**Q3: Что возвращает функция без `return`?**

`undefined`. Тело могло печатать в консоль — это побочный эффект, не результат выражения. `const x = f()` тогда `undefined`. Нужен ответ для дальнейших шагов — пиши `return`.

**Q4: Можно ли внутри функции использовать `if` и циклы?**

Да. Тело — обычные инструкции: `let`, `if`, `for`, `try`. `return` можно из ветки. Цикл внутри функции считает, затем один `return` с итогом — частый рисунок.

**Q5: Что будет, если вызвать с меньшим числом аргументов?**

Лишние параметры станут `undefined` (тема 7). Лишние аргументы сверх списка Junior может игнорировать: они не попадут в твои имена. Недостающий вход проверяй явно или дай значение по умолчанию `name = "гость"`.

## Тема 12 — Стрелочные функции

← Предыдущая тема: [11 — Объявление, параметры, `return`](#тема-11--объявление-параметры-return)  
→ Следующая тема: [13 — Лексическое окружение](#тема-13--лексическое-окружение)

---

### Теория с аналогией

**Аналогия: тот же рецепт на стикере**

«Омлет» можно написать на большом листе (`function`) или на стикере у плиты (стрелка). Блюдо то же: входы, шаги, результат. Стикер короче, когда шагов мало.

Как мы видели в 🔗 теме 11, вызов `имя(аргументы)` — выражение. Стрелка — другой способ **создать** функцию и обычно положить её в `const`.

```javascript
const add = (a, b) => {
  return a + b;
};

console.log(add(2, 3)); // 5
```

Читается: «`add` — это коробка, внутри функция: возьми `a` и `b`, верни сумму».

**Короткая форма: один выражение-результат**

Если тело — одно выражение и его же возвращаем, скобки `{ }` и `return` можно не писать:

```javascript
const add = (a, b) => a + b;

const double = (n) => n * 2;

console.log(double(4)); // 8
```

Справа от `=>` — выражение (🔗 тема 3), его значение и есть `return`. Если нужны две инструкции — только блок `{ }` и явный `return`:

```javascript
const describe = (age) => {
  if (age < 18) {
    return "рано";
  }
  return "можно";
};
```

**Один параметр — скобки можно опустить**

```javascript
const double = n => n * 2;
```

Для Junior безопаснее **всегда писать `(n)`**: глаз не путает с другими стрелками и сравнение `>=`. Ноль параметров — пустые скобки: `const hi = () => "привет"`.

**Куда класть**

Стрелку почти всегда пишут так: `const имя = (...) => ...`. Это значение в коробке. Вызвать можно только **после** этой строки: коробка ещё не создана выше (правило темы 2: объявил — потом используй).

`this`, объект `arguments` и тонкости стрелок vs `function` в обработчиках — не этот курс. Здесь стрелка = короткий `function` для расчёта и колбэков позже (🔗 тема 20).

**Схема**

```
  function add(a, b) { return a + b; }

  const add = (a, b) => a + b;
        │         │      └── выражение = неявный return
        │         └── параметры
        └── коробка с функцией
```

---

### Где это в реальном коде

- Мелкие формулы: `const tax = (sum) => sum * 0.2`.
- Колбэк `setTimeout(() => { ... }, 1000)` — когда дойдёте до асинхронности.
- `array.map((item) => item * 2)` — когда дойдёте до массивов (🔗 тема 15).
- Не тащи стрелку в огромный кусок на 40 строк: обычный `function` с именем читается лучше.

---

### Паттерны

**1. Короткая форма — только когда правда одно выражение**

Так лучше не делать: `const f = (x) => { x + 1; }` без `return` и ждать число.

Так лучше: либо `(x) => x + 1`, либо блок с `return x + 1`.

Почему: в блоке `{ }` без `return` результат снова `undefined`, как в теме 11. Фигурные включают «режим инструкций».

**2. Стрелку в `const`, вызов ниже**

Так лучше не делать: вызвать `add` строкой выше, чем `const add = ...`.

Так лучше: сначала коробка, потом `add(2, 3)`.

Почему: это `const`, не объявление `function`. Использовать до строки — ошибка.

**3. Не стреляй всем файлом**

Так лучше не делать: пять вложенных стрелок в одну строку «потому что современно».

Так лучше: короткие расчёты — стрелка; сценарий из нескольких `if` — `function` с именем.

Почему: цель — читаемость, не плотность символов.

---

### Вопросы

**Q1: Стрелка — другой вид функций в движке?**

Для Junior: это тот же инструмент «входы → шаги → результат», другой синтаксис. Вызов такой же: `имя()`. Отличия про `this` сознательно откладываем. Не думай, что стрелка «не настоящая функция».

**Q2: Когда нужен `return` у стрелки?**

Если тело в `{ }` — всегда пиши `return`, когда хочешь отдать значение. Если справа от `=>` сразу выражение без блока — `return` уже встроен. Смешал блок и забыл `return` — получишь `undefined`.

**Q3: Почему пишут `const add = ...`, а не `function`?**

Частый стиль: функция — значение в коробке, её не переназначают. Оба варианта рабочие. `function add()` удобна как «именованный рецепт» в учебном файле. Выбери один стиль в одном файле.

**Q4: Можно ли стрелку без параметров?**

Да: `const ping = () => "pong"`. Скобки обязательны, если параметров нет. С одним параметром скобки можно опустить; для учёбы оставляй их.

**Q5: Чем опасна короткая форма с объектом?**

Позже, в теме 14: `(x) => { name: x }` — фигурные решат, что это блок, не объект. Объект в короткой форме оборачивают так: `(x) => ({ name: x })`. Сейчас достаточно знать: `{` после `=>` начинается тело, не литерал, пока не добавишь скобки вокруг.

## Тема 13 — Лексическое окружение

← Предыдущая тема: [12 — Стрелочные функции](#тема-12--стрелочные-функции)  
→ Следующая тема: [14 — Объектные литералы](section_5_objects_arrays.md#тема-14--объектные-литералы)

---

### Теория с аналогией

**Аналогия: комната в квартире**

Функция — комната. На полках комнаты — параметры и `let`/`const` внутри тела. Дверь открыта в общую квартиру: то, что стоит в коридоре (переменные файла снаружи), **видно из комнаты**. Из коридора полки комнаты не видно: параметр `name` снаружи не существует.

«Лексическое» значит: смотрят на то, **где функция написана в тексте**, а не откуда её вызвали. Объявил внутри файла рядом с `const tax = 0.2` — внутри видишь `tax`.

Как мы видели в 🔗 теме 11, параметры — свои коробки на время вызова. Снаружи лежащий `const` — ещё один слой полок выше.

```javascript
const prefix = "Привет";

function greet(name) {
  console.log(prefix + ", " + name);
}

greet("Анна"); // Привет, Анна
```

`prefix` не передавали аргументом — функция всё равно его читает, потому что написана *в том же файле ниже объявления `prefix`*.

**Схема**

```
  файл (коридор)
    const prefix = "Привет"
    function greet(name)
      │
      ├── полка комнаты: name
      └── смотрит наружу: prefix

  снаружи нет коробки name
```

**Тень имени**

Если внутри объявить то же имя, внутреннее **закрывает** наружное на время тела:

```javascript
const title = "курс";

function show() {
  const title = "урок";
  console.log(title); // урок
}

show();
console.log(title);   // курс
```

Внутри `show` слово `title` — другая коробка. Наружный `title` не испортился. Это не баг: два этажа, одинаковая табличка.

**Внутреннее наружу не вытекает**

```javascript
function make() {
  const secret = 42;
  return secret + 1;
}

make();
// console.log(secret); // ошибка: secret is not defined
```

Коробка `secret` живёт только во время вызова `make`. После `return` комнату убрали. Чтобы значение жило снаружи — `return`, как в теме 11.

**Функция помнит коридор, даже если вызов позже**

Пока без термина «замыкание» как интервью-темы. Достаточно факта:

```javascript
const n = 10;

function plusN(x) {
  return x + n;
}

console.log(plusN(5)); // 15
```

`plusN` при каждом вызове читает текущий `n` снаружи. Если `n` был `let` и ты его изменил до вызова — внутри увидят новое значение. Для настроек чаще `const`, чтобы не удивляться.

Вложенные функции и «фабрика счётчиков» — глубже, в middle. Junior-правило: **внутри видно снаружи по тексту; снаружи не видно внутреннее**.

---

### Где это в реальном коде

- Файл скрипта: `const TAX = 0.2` наверху, функции расчёта читают `TAX`, не тащат её десятым аргументом.
- Сообщение об ошибке: общая `const APP = "касса"` клеится внутри нескольких функций.
- Обработчик клика позже закроет переменные страницы — тот же принцип «написан рядом — видит».
- Не складывай в коридор всё подряд: тогда непонятно, кто меняет `let`. Аргументы всё ещё лучший вход для *разных* вызовов.

---

### Паттерны

**1. Настройка файла — `const` снаружи, расчёт — аргументы**

Так лучше не делать: десять `let` наверху, все функции их читают и пишут.

Так лучше: неизменное (`TAX`, имя приложения) — снаружи `const`. То, что разное на вызов (`price`, `name`) — параметры.

Почему: видно зависимости. Случайный `let` в коридоре — общий черновик на всех.

**2. Не дублируй имя снаружи и внутри без нужды**

Так лучше не делать: снаружи `const name`, внутри ещё `const name`, потом час искать «почему не то имя».

Так лучше: внутри `userName` или параметр `name`, снаружи другое слово.

Почему: тень работает по правилам, но мозг путает этажи.

**3. Нужно значение после вызова — `return`, не надежда на наружный `let`**

Так лучше не делать: функция пишет в `let result` снаружи, вызывающий читает `result`.

Так лучше: `return` и `const result = f()`.

Почему: два вызова подряд затрут черновик. Выражение вызова из темы 11 как раз для этого.

### Вопросы

**Q1: Почему функция видит переменную, которую ей не передали?**

Потому что она *написана* в том же окружении, где эта переменная объявлена. Движок при выполнении тела ищет имя сначала в комнате (параметры, внутренние `let`), потом в коридоре файла. Это лексика: место в тексте, не место вызова.

**Q2: Почему снаружи не виден `const` из тела функции?**

Комната закрыта. Имя существует, пока идёт вызов. После `return` внутренних полок нет. Это защищает от случайного использования чужого черновика и заставляет явно `return`, если ответ нужен миру.

**Q3: Что такое «тень» имени?**

Внутреннее объявление с тем же словом, что снаружи. Внутри тела наружное имя не доступно под этим словом — его закрыли. После выхода из функции наружная коробка как была. Не путай с переназначением одного `let`.

**Q4: Это уже замыкание?**

Замыкание — когда внутренняя функция уносится наружу и всё равно помнит коридор. В Junior достаточно: «снаружи видно внутри по месту в коде». Фабрики функций и счётчики в замыкании — middle (там же тема «замыкания на практике»). Не зубрить термин, пока не жжёт задача.

**Q5: Передавать аргументом или читать снаружи?**

Разное на каждый вызов — аргумент. Одно на весь файл (налог, название) — наружный `const`. Если сомневаешься — аргумент: зависимость видна в вызове `total(price, tax)`.

### Практическое задание

Файл `scope.js`.

1. Снаружи `const greetPrefix = "Здравствуй"`.
2. Функция `greet(name)` печатает `greetPrefix` и `name` (шаблон или `+`).
3. Функция `area(width, height)` с внутренним `const unit = "м²"` возвращает строку с площадью и единицей. Снаружи `unit` не используй.
4. Вызови обе. Строкой-комментарием напиши, что будет, если сделать `console.log(unit)` под функциями.

---

### Решение с инсайтом

```javascript
const greetPrefix = "Здравствуй";

function greet(name) {
  console.log(`${greetPrefix}, ${name}`);
}

function area(width, height) {
  const unit = "м²";
  return `${width * height} ${unit}`;
}

greet("Анна");
console.log(area(3, 4));

// console.log(unit); // ошибка: unit живёт только внутри area
```

**Инсайт:** внутри видно коридор. Коридор не видит комнату. Нужен ответ снаружи — `return`, не общая глобальная свалка.
