# Раздел 8 — Модули

Пока весь учебный код жил в одном файле (🔗 тема 1). Когда появляются `wait`, `fetch` и работа с DOM, один `app.js` перестаёт читаться. **Модуль** — файл, который явно отдаёт наружу выбранные имена и явно берёт чужие. Без сравнения ESM и CommonJS на уровне бандлеров: рабочий инструмент — `import` / `export`.

### Теория с аналогией

**Аналогия: коробка с описью**

Файл — коробка. На крышке список: «отсюда можно взять `add` и `TAX`». Соседняя коробка не роется внутри без описи: только то, что **экспортировали**. `import` — «возьми с описи той коробки».

Как мы видели в 🔗 теме 11, функции — рецепты с именами. Модуль решает, какие рецепты публичные. Как в 🔗 теме 13, то что не экспортировали, снаружи не видно — это уже не «комната функции», а «крышка файла».

**Именованный экспорт**

```javascript
// math.js
export const TAX = 0.2;

export function add(a, b) {
  return a + b;
}

function secret() {
  return 42;
}
// secret снаружи math.js нет
```

```javascript
// app.js
import { add, TAX } from "./math.js";

console.log(add(2, 3));
console.log(TAX);
```

Имена в `{ }` должны совпасть с экспортом. Путь `./math.js` — относительно текущего файла, **с расширением** в браузере и в современном Node (ESM).

**Экспорт по умолчанию**

Один «главный» предмет файла:

```javascript
// greet.js
export default function greet(name) {
  console.log("Привет, " + name);
}
```

```javascript
import greet from "./greet.js";
// имя слева выбираешь сам: import hello from "./greet.js";
```

В одном файле можно смешать default и именованные, но Junior проще: **либо несколько именованных, либо один default**. Не плоди оба стиля в каждом файле.

**Браузер**

```html
<script type="module" src="app.js"></script>
```

Без `type="module"` `import` в файле не работает. Модули грузятся с сервера (Live Server): `file://` часто режет загрузку модулей. Как в теме 1 — удобнее Live Server, не сырой двойной щелчок.

**Node**

В `package.json` поле `"type": "module"` или расширение `.mjs`. Иначе старый стиль `require` — его **не используй** как привычку курса. Если видишь `require("./math")` в легаси — это CommonJS, другая описи. Сравнивать бандлеры Webpack/Vite — не эта тема.

**Схема**

```
  math.js                 app.js
  export add, TAX    →    import { add, TAX } from "./math.js"
  (secret спрятан)
```

Цикл `a` импортирует `b`, `b` импортирует `a` — избегай. Разрежь третьим файлом с общими константами.

### Где это в реальном коде

- `wait.js` из темы 21 → `import { wait } from "./wait.js"` в `async-wait.js`.
- `dom.js`: только работа с узлами; `api.js` — только `fetch`.
- Кнопка в HTML по-прежнему один вход: `app.js` с `type="module"` тянет остальное.

### Паттерны

**1. Явный список экспорта**

Так лучше не делать: всё подряд `export`, включая черновики.

Так лучше: наружу 1–3 имени, остальное без `export`.

Почему: описи короткие. Сосед не зависит от внутренней `secret`.

**2. Путь с `./` и `.js`**

Так лучше не делать: `from "math"` без пути, как npm-пакет, если это твой файл рядом.

Так лучше: `from "./math.js"`. Пакет из `node_modules` — имя без `./` (`import fs from "node:fs"` в Node).

Почему: без `./` движок ищет пакет, не соседний файл. Без `.js` браузер часто 404.

**3. Один стиль на проект**

Так лучше не делать: в одном файле default `add`, в другом `{ add }`.

Так лучше: утилиты — именованные экспорты. «Главный компонент файла» — default, если команда так договорилась.

Почему: `import add from` vs `import { add }` — вечная путаница при смешении.

### Вопросы

**Q1: Чем модуль отличается от просто второго `.js` с двумя тегами `script`?**

Два обычных `script` делят глобальную кучу: порядок тегов важен, имена сталкиваются. Модули изолированы: видно только `import`. Порядок задаёт граф импортов, не расположение десяти тегов.

**Q2: Почему в браузере нужен `type="module"`?**

Обычный скрипт не умеет `import`/`export` как модуль. Атрибут включает разбор ESM, строгий режим и загрузку зависимостей. Без него синтаксическая ошибка на `import`.

**Q3: Можно ли `import` внутри `if` как обычную строку?**

Классический `import` — вверху файла, не в ветке. Условная загрузка — `import()`-функция (динамический импорт), не база Junior. Сначала статические импорты сверху.

**Q4: Что будет, если забыть `export`?**

`import { add }` упадёт: имени нет в описи. Функция в файле есть, для соседа её нет. Это не `undefined` тихо, а ошибка загрузки модуля.

**Q5: Нужно ли учить `require` и `module.exports`?**

Чтобы читать старый Node-код — узнать, что они существуют. Писать новый учебный код — ESM. Спор «что лучше в 2015» и настройка Webpack — middle / практика работы, не эта тема.

### Практическое задание

Три файла (Node с `"type": "module"` или браузер + `type="module"` + Live Server).

1. `math.js`: `export function double(n)` — вернуть `n * 2`.
2. `app.js`: `import { double } from "./math.js"`, выведи `double(4)`.
3. В `math.js` оставь внутреннюю функцию без `export` и **не** пытайся её импортировать.
4. Если браузер: HTML только с `<script type="module" src="app.js">`.

---

### Решение с инсайтом

```javascript
// math.js
export function double(n) {
  return n * 2;
}

function unusedHint() {
  return "не экспортируем";
}
```

```javascript
// app.js
import { double } from "./math.js";

console.log(double(4)); // 8
```

```html
<script type="module" src="app.js"></script>
```

**Инсайт:** модуль отдаёт только опись. `import` — явная зависимость, не общая глобальная свалка имён.
