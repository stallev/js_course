# Раздел 5 — Объекты и массивы

Примитивы — одно значение в коробке (🔗 тема 4). Человек, товар, список покупок — **несколько** значений вместе. Объект — подписанные полки (`name`, `age`). Массив — нумерованная очередь (`0`, `1`, `2`).

Тема 16 объяснит, почему `const b = a` для объекта — не вторая куча вещей, а вторая табличка на ту же кучу. Пока учим читать и собирать.

### Теория с аналогией

**Аналогия: карточка в картотеке**

Одна карточка: поля «имя», «город», «возраст». Не три разрозненные коробки `name`, `city`, `age`, которые легко перепутать, а **один** предмет с подписями.

Как мы видели в 🔗 теме 2, `const` запрещает подменить коробку целиком. Поля внутри карточки при этом можно менять — это не противоречие, разберём в теме 16. Сейчас: собираем карточку литералом `{ }`.

```javascript
const user = {
  name: "Анна",
  age: 20,
  city: "Казань",
};

console.log(user.name); // Анна
console.log(user.age);  // 20
```

Слева ключ (имя полки), справа значение — любое выражение (🔗 тема 3): строка, число, даже результат функции.

**Точка и скобки**

```javascript
user.name;           // точка — ключ известен заранее
user["name"];        // то же

const key = "city";
console.log(user[key]); // Казань — ключ в переменной, только скобки
```

Точка не умеет `user.key`, если хотели значение переменной `key`: это полка с именем `"key"`. Для вычисляемого имени — `user[key]`.

**Нет полки — `undefined`**

```javascript
console.log(user.phone); // undefined  (тема 7: не клали)
```

Не путай с `null`: поле не объявляли. Проверка: `user.phone === undefined`.

**Запись и удаление**

```javascript
user.age = 21;
user.hobby = "бег";     // новая полка
delete user.hobby;
```

**Метод — функция на карточке**

Как в 🔗 теме 11, функция — набор шагов. Её можно положить в поле:

```javascript
const counter = {
  value: 0,
  bump() {
    this.value = this.value + 1;
  },
};

counter.bump();
console.log(counter.value); // 1
```

`this` здесь — **тот объект, у которого вызвали метод** (`counter` до точки). Не разворачиваем `call`/`bind` и не путаем со стрелками: для Junior достаточно «в методе `this` — карточка слева от точки». Если метод не смотрит на поля карточки, `this` не нужен.

Коротко: `bump() { ... }` внутри литерала — то же, что `bump: function () { ... }`.

**`typeof` и вложенность**

```javascript
console.log(typeof user); // "object"

const order = {
  id: 1,
  buyer: {
    name: "Анна",
  },
};

console.log(order.buyer.name); // Анна
```

`null` тоже врёт ярлыком `"object"` (🔗 тема 4). Объект проверяй не одним `typeof`, а «это не `null` и `typeof === "object"`», когда дойдёшь до развилки.

**Схема**

```
  user
    ├── name: "Анна"
    ├── age: 20
    └── city: "Казань"

  user.name     →  значение с полки name
  user["city"]  →  то же, ключ строкой
```

---

### Где это в реальном коде

- Настройки скрипта: `const config = { port: 3000, host: "localhost" }`.
- Ответ `JSON.parse` (🔗 тема 10) — обычный объект, поля через точку.
- Позже DOM: у элемента тоже «поля» (`textContent`) — похожая мысль, другая тема (17).
- Функция возвращает несколько значений одной карточкой: `return { ok: true, age: 20 }`.

---

### Паттерны

**1. Связанные данные — один объект, не россыпь переменных**

Так лучше не делать: `const userName`, `const userAge`, `const userCity` и передавать три аргумента везде.

Так лучше: `const user = { name, age, city }` и `greet(user)`.

Почему: один предмет в голове и в вызове. Меньше шанс забыть четвёртое поле.

**2. Имена ключей — как у переменных**

Так лучше не делать: `user.n`, `user.d1`.

Так лучше: `user.name`, `user.createdAt`.

Почему: точка читается вслух. Сокращения живы только в голове автора.

**3. Не читай поле, которого можешь не быть, без проверки**

Так лучше не делать: `order.buyer.name`, если `buyer` бывает `null`.

Так лучше: сначала `if (order.buyer !== null && order.buyer !== undefined)`, потом `.name`. (Позже появится `?.` — не этот раздел.)

Почему: иначе ошибка «нельзя читать property of null» — скрипт падает, `try` тут не обязан быть первой линией защиты.

---

### Вопросы

**Q1: Чем объект отличается от набора отдельных переменных?**

Это одно значение (карточка) с несколькими подписанными полями. Его можно передать в функцию целиком, вернуть из функции, положить в массив. Три `const` наверху файла не составляют «человека» для движка — только для тебя в комментарии.

**Q2: Когда точка, когда квадратные скобки?**

Ключ-идентификатор заранее известен — точка: `user.age`. Ключ в переменной или с пробелом/символом — скобки: `user[key]`. Для учёбы 90% случаев — точка.

**Q3: Почему `const user` не мешает писать `user.age = 21`?**

`const` запрещает `user = { ... другой объект }`. Сама карточка та же, меняется содержимое полок. Подмена всей коробки и правка поля — разные операции. Тема 16 покажет, что «та же карточка» важна, когда копируешь имя.

**Q4: Что такое метод?**

Поле, в котором лежит функция. Вызов `counter.bump()` запускает эту функцию. Чтобы метод видел поля этой же карточки, используют `this` — объект до точки. Глубже (`this` в отрыве от объекта, стрелки) — middle.

**Q5: Чем `user.phone === undefined` отличается от «поля нет» и `null`?**

Нет полки и полка с `undefined` для чтения выглядят одинаково: `undefined`. `null` — сознательно положили пусто (тема 7). Если API обещает `phone: null`, проверяй `=== null`. Если поле просто забыли — будет `undefined`.


**Инсайт:** объект — одна карточка с подписями, не россыпь переменных. Точка читает полку. Метод — функция на карточке, `this` — эта карточка при вызове через точку.

## Тема 15 — Массивы и базовые методы

→ Следующая тема: [16 — Ссылка и копия](#тема-16--ссылка-и-копия)

### Теория с аналогией

**Аналогия: очередь лотков**

Лотки стоят в ряд: первый, второй, третий. Номер с **нуля**. Длина очереди — сколько лотков сейчас.

Массив — объект-список. `typeof []` даст `"object"`; отличить список помогает `Array.isArray(value)`.

Как мы видели в 🔗 теме 9, `for...of` уже ходил по элементам. Здесь — создать список, добавить, найти, получить новый список.

```javascript
const prices = [150, 200, 90];

console.log(prices[0]);      // 150
console.log(prices.length);  // 3
console.log(prices[3]);      // undefined — лотка нет
```

**Добавить и снять с конца**

```javascript
prices.push(300);  // в конец
console.log(prices.length); // 4

const last = prices.pop();  // сняли 300
console.log(last);
```

`push` / `pop` меняют **тот же** массив (тема 16 объяснит, почему это важно).

**Перебор**

```javascript
for (const price of prices) {
  console.log(price);
}

for (let i = 0; i < prices.length; i = i + 1) {
  console.log(i, prices[i]); // нужен номер — классический for
}
```

**`map` / `filter` / `find` — «умею вызвать»**

Колбэк — функция из тем 11–12. Её вызовут для элемента.

```javascript
const doubled = prices.map((price) => price * 2);
// новый массив, исходный не обязался измениться

const cheap = prices.filter((price) => price < 200);
// только те, для кого колбэк дал правду

const firstCheap = prices.find((price) => price < 200);
// первый подходящий элемент или undefined
```

Не обязательно писать `map` руками через `for` — но понимать: внутри тот же цикл. `forEach` печатает побочный эффект; для нового списка чаще `map`.

`reduce` в Junior не обязателен: сначала `for` или `map`/`filter`.

**Схема**

```
  индекс:    0      1      2
  prices:  [150]  [200]  [ 90]
             └── length === 3

  push → лоток в конец, length + 1
  map  → новая очередь той же длины (обычно)
```

---

### Где это в реальном коде

- Список имён для печати: `for...of` или `names.map`.
- Товары дешевле порога: `filter`.
- Первый статус `"ok"` в списке ответов: `find`.
- JSON-массив с сервера: `data.items[0].name` — массив объектов (тема 14 + 15).

---

### Паттерны

**1. Индекс с нуля, граница — `length`**

Так лучше не делать: `prices[prices.length]` в ожидании последнего.

Так лучше: последний — `prices[prices.length - 1]` или `at` не обязательно учить сейчас; либо `prices[i]` в цикле `i < length`.

Почему: индекс `length` всегда «за концом» → `undefined`.

**2. Нужен новый список — `map`/`filter`, не копипаста `push` вслепую без цели**

Так лучше не делать: путать `map` с `forEach` и ждать, что `forEach` вернёт массив.

Так лучше: преобразование → `map`, отбор → `filter`, один элемент → `find`, просто пройтись с логом → `for...of` / `forEach`.

Почему: у каждого метода свой ответ. `map` без `return` в колбэке наполняет список `undefined`.

**3. Не используй `for...in` по массиву**

Так лучше не делать: `for (const i in prices)`.

Так лучше: `for...of` по значениям или `for` по индексу.

Почему: `for...in` для ключей объекта (и лишнего). Для очереди лотков он путает. Тема 9 уже просила так не делать.

---

### Вопросы

**Q1: Чем массив отличается от объекта `{ 0: 150, 1: 200 }`?**

Оба родственники, но массив заточен под порядок и `length`, плюс методы `push`, `map`. Объект — подписи-имена. Список однотипного — массив. Карточка с полями `name`/`age` — объект. Смешивать «массив с дырками по именам» без нужды не стоит.

**Q2: Почему нумерация с нуля?**

Так устроен язык: первый лоток — индекс `0`. `length` при этом — количество, не последний индекс. Последний индекс — `length - 1`. Пустой массив: `length === 0`, к `[0]` не обращайся без проверки.

**Q3: `map` меняет исходный массив?**

Обычный `map` **возвращает новый** массив и исходный не трогает. `push`/`pop` трогают исходный. Если после `map` старый список «вдруг» другой — ищи свой код с `push` или присваивание в элемент `prices[i] = ...`.

**Q4: Что вернёт `find`, если ничего не подошло?**

`undefined`. Проверяй результат, прежде чем читать поле `.name`. `filter` в том же случае вернёт **пустой массив** `[]`, не `undefined`. Пустой список — валидное значение, `length === 0`.

**Q5: Нужно ли запоминать все методы массива?**

Нет. База: индекс, `length`, `push`/`pop`, `for...of`, `map`, `filter`, `find`. Остальное (`slice`, `includes`, `join`) откроешь по задаче. Смысл колбэка важнее списка имён.

### Практическое задание

Файл `prices.js`.

1. Массив `prices` из четырёх чисел.
2. Выведи первый элемент и `length`.
3. `push` ещё одно число, затем выведи `length` снова.
4. `const doubled = prices.map(...)` — каждое × 2.
5. `const cheap = prices.filter(...)` — строго меньше 200.
6. `find` первое число меньше 100 (или другое условие, если в данных нет). Выведи все три результата.

### Решение с инсайтом

```javascript
const prices = [150, 200, 90, 40];

console.log(prices[0], prices.length);

prices.push(300);
console.log(prices.length);

const doubled = prices.map((price) => price * 2);
```

**Инсайт:** массив — очередь с индексом с нуля. `push` меняет её. `map`/`filter`/`find` — цикл с колбэком и разным типом ответа (новый список / новый список короче / один элемент).

### Что дальше

## Тема 16 — Ссылка и копия

← Предыдущая тема: [15 — Массивы и базовые методы](#тема-15--массивы-и-базовые-методы)  
→ Следующая тема: [17 — DOM: поиск узлов, текст, атрибуты](section_6_dom_events.md#тема-17--dom-поиск-узлов-текст-атрибуты)

---

### Теория с аналогией

**Аналогия: табличка на одной коробке**

Примитив (число, строка, булево): в коробке лежит само значение. Положил в другую коробку — **вторая куча песка**, первая не меняется.

Объект и массив: в коробке лежит **адрес** склада (ссылка). Вторая переменная с тем же адресом указывает на тот же склад. Покрасил полку через одно имя — видно через другое.

Как мы видели в 🔗 теме 14, `const user` не мешает менять поля: меняется склад, не табличка. Тема 2: `const` держит табличку, не содержимое склада.

```javascript
let a = 10;
let b = a;
b = 20;
console.log(a); // 10 — песок скопировали

const user = { name: "Анна" };
const alias = user;
alias.name = "Павел";
console.log(user.name); // Павел — тот же склад
```

**Схема**

```
  число:     a → [10]          b → [10]     две кучи

  объект:    user ──┐
                    ├──► { name: "Анна" }
             alias ─┘
```

`user === alias` — `true`: один и тот же склад. Два литерала `{ name: "Анна" }` — разные склады, даже если поля похожи: `===` будет `false`.

**Поверхностная копия — новый склад, старые внутренности**

Нужна **другая** очередь/карточка, чтобы `push` не портил оригинал:

```javascript
const prices = [150, 200];
const copy = [...prices]; // новый массив, те же числа-примитивы
copy.push(90);
console.log(prices.length); // 2
console.log(copy.length);   // 3
```

```javascript
const user = { name: "Анна", age: 20 };
const copy = { ...user }; // новый объект, поля скопированы
copy.age = 21;
console.log(user.age); // 20
```

`...` здесь — «разложи полки/элементы в новый литерал». Этого хватает, пока внутри примитивы.

Если поле само объект — копируется **ссылка на внутренний** склад:

```javascript
const order = { buyer: { name: "Анна" } };
const copy = { ...order };
copy.buyer.name = "Павел";
console.log(order.buyer.name); // Павел — внутренний склад общий
```

Глубокая копия (все этажи) — отдельная задача (`structuredClone` в современной среде или аккуратный ручной разбор). Junior: помни, что `{...}` / `[...]` — **один этаж**.

`JSON.parse(JSON.stringify(obj))` копирует глубже, но отваливает функции и `undefined`. Не серебряная пуля.

**Схема копии**

```
  [...arr]  /  { ...obj }

  новый склад (этаж 1)
  полки-примитивы — свои
  полки-объекты   — старые адреса (этаж 2 общий)
```

---

### Где это в реальном коде

- Функция получила массив и сделала `push` — испортила список снаружи. Либо копируй на входе, либо возвращай новый массив через `map`.
- «Сброс формы»: не мутируй объект настроек по умолчанию, работай с копией.
- Два компонента (позже мысль) держат один и тот же объект состояния — правка в одном месте видна в другом. Пока: не отдавай наружу свой внутренний массив, если не хочешь, чтобы его пушили.

---

### Паттерны

**1. Не путай «новое имя» и «новый склад»**

Так лучше не делать: `const copy = original;` и `copy.push(1)` в надежде, что `original` цел.

Так лучше: `const copy = [...original]` или `map`, если нужна другая очередь.

Почему: присвоение объекта копирует адрес, не склад.

**2. Либо меняй один массив, либо строй новый — не смешивай без мысли**

Так лучше не делать: то `push` в исходный, то `map`, и не понимать, какая переменная актуальная.

Так лучше: явно «этот список живой, его пушим» или «считаем `const next = filter(...)` и дальше только `next`».

Почему: баги «пропал элемент» почти всегда из общей ссылки.

**3. Вложенные объекты копируй сознательно**

Так лучше не делать: `{ ...order }` и менять `copy.buyer.name`, думая, что заказ-источник свят.

Так лучше: либо не мутировать вложенное, либо копировать этаж: `{ ...order, buyer: { ...order.buyer } }`.

Почему: поверхностная копия копирует адреса вложенных карточек.

---

### Вопросы

**Q1: Почему после `const b = a` правка `b.name` меняет `a`?**

`a` и `b` хранят один адрес. Правка полки на складе видна всем табличкам. У числа `b = a` кладёт в `b` копию цифры, склады разные.

**Q2: `const` спасает от такой правки?**

Нет. `const` запрещает `b = другойОбъект`. Полки склада не заморожены. Защита «никто не подменит табличку», не «никто не переклеит этикетку внутри».

**Q3: Как сделать независимый массив чисел?**

`const copy = [...prices]` или `prices.map((x) => x)` / `prices.slice()`. Потом `push` в `copy` не удлиняет `prices`. Для массива объектов внутри элементы всё ещё общие ссылки — как вложенные карточки.

**Q4: Почему `{ name: "Анна" } === { name: "Анна" }` — `false`?**

Два литерала — два склада. `===` для объектов спрашивает «тот же адрес?», не «поля похожи?». Сравнить содержимое — сравни поля явно (`a.name === b.name`) или позже утилита. Не жди, что `===` глубоко пройдётся по полкам.

**Q5: Нужно ли сейчас глубокое клонирование всего дерева?**

Редко. Сначала пойми этаж: один `{...}` копирует верх. Вложенность трогай, только если реально меняешь внутреннюю карточку. Универсальный «клон всего» без понимания ссылок прячет баг, а не лечит.

### Практическое задание

Файл `copy-demo.js`.

1. `const user = { name: "Анна" }`, `const alias = user`. Поменяй `alias.name`, выведи `user.name`.
2. `const independent = { ...user }`. Поменяй `independent.name`, выведи оба имени.
3. `const prices = [1, 2]`, `const same = prices`, `same.push(3)` — выведи `prices`.
4. `const other = [...prices]` (после пункта 3 или на свежем массиве), `other.push(99)` — покажи, что исходник пункта с копией не обязан расти так же. Комментарием своими словами: чем `alias` отличается от `{ ...user }`.

### Решение с инсайтом

```javascript
const user = { name: "Анна" };
const alias = user;
alias.name = "Павел";
console.log(user.name); // Павел — тот же склад

const independent = { ...user };
independent.name = "Оля";
console.log(user.name);         // Павел
console.log(independent.name);  // Оля

const prices = [1, 2];
const same = prices;
same.push(3);
console.log(prices); // [1, 2, 3]

const other = [...prices];
other.push(99);
console.log(prices); // [1, 2, 3]
console.log(other);  // [1, 2, 3, 99]

// alias = тот же адрес. { ...user } = новый склад верхнего этажа.
```

**Инсайт:** примитив копирует значение, объект и массив — адрес. Новое имя ≠ новая куча. `{...}` и `[...]` строят новый верхний этаж.
