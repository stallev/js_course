# Раздел 1 — Среда и синтаксис

Пока код не запускается, остальное — разговор о языке в вакууме. Этот раздел отвечает на три бытовых вопроса: *где* выполняется JavaScript, *куда* класть значения, *из чего* состоит строка кода.

Темы идут от «открыл файл» к «понимаю, что написал». Event Loop, типы и функции — позже; сейчас нужна рабочая привычка: написать → запустить → увидеть результат.

## Тема 1 — Как запускается JavaScript

← Предыдущая тема: нет (это начало курса)  
→ Следующая тема: [2 — Переменные: `let` и `const`](#тема-2--переменные-let-и-const)

### Теория с аналогией

**Аналогия: рецепт и кухня**

JavaScript — это рецепт (текст в файле `.js`). Сам по себе файл ничего не готовит. Нужна кухня: программа, которая читает рецепт и выполняет шаги. Таких кухонь две, и они встречаются каждый день.

| Кухня | Где живёт | Типичная еда |
|-------|-----------|----------------|
| **Браузер** | Chrome, Firefox, Edge | Кнопка на сайте, изменение текста на странице |
| **Node.js** | Терминал на компьютере | Скрипт, который печатает в консоль, читает файл, запускает сервер |

Один и тот же язык, разные возможности вокруг: в браузере есть страница (DOM), в Node — файлы и процесс, но нет кнопки «на сайте».

**Схема: от файла до результата**

```
  hello.js          движок JS           результат
  (текст)    →      читает построчно  →  консоль / страница
                    и выполняет
```

Движок не «понимает намерения». Он выполняет то, что написано, сверху вниз, пока не закончится файл (пока мы не дойдём до функций и событий — 🔗 Связь с темой 11 и темой 18).

**Запуск в браузере**

Страница — HTML. JavaScript подключают тегом `script`:

```html
<!DOCTYPE html>
<html>
  <body>
    <p id="status">Ещё не запускали</p>
    <script src="hello.js"></script>
  </body>
</html>
```

```javascript
// hello.js
console.log("Привет из браузера");
```

Открой HTML через Live Server или просто двойным щелчком. Консоль: в DevTools клавиша `F12` → вкладка **Console**. `console.log` пишет туда, а не на саму страницу.

Скрипт в конце `body` — простой и понятный порядок: сначала разметка, потом код. Подробности про поиск элементов — в 🔗 теме 17.

**Запуск в Node.js**

В терминале, в папке с файлом:

```bash
node hello.js
```

```javascript
// hello.js
console.log("Привет из Node");
```

Строка появится прямо в терминале. Не нужен HTML. Нужны установленный Node.js и файл с расширением `.js`.

**Консоль — не программа, а окно**

`console.log` — способ *посмотреть*, что произошло. Это не «вывод для пользователя сайта». Для пользователя позже будут текст в DOM и ответы сервера. Для учёбы консоль — главный прибор.

---

### Где это в реальном коде

- Лендинг: `index.html` + `main.js`, скрипт внизу страницы, проверка в DevTools.
- Учебный файл: `node calculate.js` — сложил два числа, увидел сумму в терминале.
- Расширение VS Code / скрипт деплоя: тоже Node, тот же `node файл.js`.
- Встроенный скрипт: `<script>console.log(1)</script>` — удобно для одной строки, для курса лучше отдельный `.js`.

Пока не используем `import` (🔗 тема 25): один файл, запуск целиком.

---

### Паттерны

**1. Где лежит скрипт**

Так лучше не делать: огромный код внутри HTML между `<script>` и `</script>` — страницу тяжело читать, код нельзя открыть отдельно.

Так лучше: `src="app.js"` и логика в файле.

Почему: один файл — одна ответственность. HTML описывает структуру, JS — поведение.

**2. Куда смотреть, если «ничего не произошло»**

Так лучше не делать: менять код и обновлять страницу, не открывая консоль.

Так лучше: сразу `F12` → Console. Красная ошибка (файл не найден, опечатка) видна там.

Почему: браузер часто молчит на странице, но пишет причину в консоль.

**3. Одна среда за раз, пока учишься**

Так лучше не делать: копировать в Node код с `document.querySelector` — в Node нет страницы, будет ошибка.

Так лучше: браузерные примеры — в HTML+JS, терминальные — в `node`.

Почему: падает не «JavaScript сломался», а «этой кухни нет на этой кухне».

---

### Вопросы

**Q1: Чем файл `.js` отличается от запущенной программы?**

Файл — текст рецепта. Пока его не прочитает браузер или Node, ничего не выполняется. Запуск — это момент, когда движок начинает идти по строкам. Поэтому «я написал код» и «я увидел результат» — два разных шага. Junior-привычка: после каждой порции кода запускать и смотреть консоль.

**Q2: Зачем тег `script` в HTML?**

HTML сам по себе не выполняет JavaScript. Тег `script` говорит браузеру: «вот код, который нужно запустить для этой страницы». Атрибут `src` указывает файл. Без этого тега `hello.js` просто лежит на диске. Порядок в HTML важен: скрипт в конце `body` видит уже нарисованные элементы.

**Q3: Что делает `console.log` и где искать вывод?**

Это команда «напиши в журнал отладки». В браузере журнал — вкладка Console в DevTools. В Node — окно терминала, где вызвали `node`. Пользователь сайта этот журнал обычно не видит. Для учёбы этого достаточно, чтобы проверить, что строка вообще выполнилась.

**Q4: Можно ли один и тот же `.js` запустить и в браузере, и в Node?**

Если в файле только язык: числа, строки, `console.log` — часто да. Если есть `document` или `window` — это браузер, Node упадёт. Если есть `fs` (файлы Node) — браузер не поймёт. Сначала пишите код без привязки к среде, потом добавляйте «кухонные» объекты.

**Q5: Я открыл HTML, страница белая, кода как будто нет. С чего начать проверку?**

Путь в `src`: опечатка в имени файла, файл в другой папке. Консоль покажет `Failed to load resource` или ошибку синтаксиса. Второй шаг — есть ли вообще `console.log` в файле и сохранился ли файл перед обновлением. Третий — не открыт ли старый кэш: жёсткое обновление или Live Server.

## Тема 2 — Переменные: `let` и `const`

← Предыдущая тема: [1 — Как запускается JavaScript](#тема-1--как-запускается-javascript)  
→ Следующая тема: [3 — Выражения, инструкции, комментарии](#тема-3--выражения-инструкции-комментарии)

---

### Теория с аналогией

**Аналогия: коробки с подписями на столе**

Переменная — коробка. На коробке имя (`userName`), внутри — значение (`"Анна"`). Движок не «помнит смысл», он кладёт и достаёт по имени.

Как мы видели в 🔗 теме 1, код идёт сверху вниз. Сначала создаём коробку, потом кладём или читаем. Обратиться к имени до создания — ошибка. Подробный разбор «зоны до объявления» — в middle-курсе; здесь правило проще: **объявил — потом используй**.

**`let` — содержимое можно заменить**

```javascript
let temperature = 18;
console.log(temperature); // 18

temperature = 21;         // положили новое число в ту же коробку
console.log(temperature); // 21
```

Имя то же, значение другое. Это нормально для счётчика, статуса, ввода пользователя.

**`const` — коробку не меняем**

```javascript
const city = "Казань";
console.log(city);

// city = "Москва";  // ошибка: Assignment to constant variable
```

`const` не значит «значение навсегда во всей программе». Значит: **этой переменной нельзя присвоить другое значение**. Для имени, которое не должно «случайно перезаписать», бери `const`.

Позже, когда появятся объекты (🔗 тема 14), выяснится: у `const` объекта можно менять поля внутри, нельзя подменить всю коробку. Сейчас достаточно: для чисел и строк `const` = не переназначай.

**Имена**

```javascript
let userAge = 20;      // понятно
const MAX_ATTEMPTS = 3; // константа-лимит, часто КАПС

// так лучше не называть:
let x = 20;
let a1 = "Казань";
```

Имя — часть кода для человека. Правила стиля подробнее в 🔗 теме 26.

**`var` — не рабочий инструмент этого курса**

В старых примерах встречается `var`. У него другие правила видимости, из-за них легко запутаться. В Junior пишем только `let` и `const`. Если увидишь `var` в чужом коде — читай как «старая переменная», сам не добавляй.

**Схема**

```
const name = "Анна"
      │         │
      │         └── значение (что лежит)
      └── имя (как зовём)

let count = 0
count = count + 1     ← достали 0, прибавили 1, положили 1 обратно
```

---

### Где это в реальном коде

- Скрипт приветствия: `const userName = "Гость"` — имя не должно стёрться следующей строкой.
- Счётчик кликов (когда дойдём до событий, 🔗 тема 18): `let clicks = 0`, потом `clicks = clicks + 1`.
- Node-скрипт: `const fileName = "data.json"` — путь к файлу не переназначаем.
- Настройки: `const PORT = 3000` в маленьком сервере на Node.

Пока нет DOM — проверяй переменные через `console.log`, как в теме 1.

---

### Паттерны

**1. Сначала `const`, `let` — если точно будешь менять**

Так лучше не делать: все переменные через `let` «на всякий случай».

Так лучше: `const`, пока не понадобилось присваивание ещё раз.

Почему: случайное `name = ...` ниже по файлу не сломает то, что должно быть стабильным. Глаз сразу видит: это значение фиксировано.

**2. Объявил — сразу осмысленное значение, если оно есть**

Так лучше не делать: `let total;` и десять строк спустя первое использование — легко забыть присвоить.

Так лучше: `let total = 0;` в момент, когда счётчик появляется.

Почему: пустая коробка (`undefined`) — частый сюрприз. Тема 7 разберёт `undefined` отдельно; не плоди его без нужды.

**3. Одно имя — одна роль**

Так лучше не делать: `let data = 1;` потом `data = "ок";` — в одной коробке то число, то строка.

Так лучше: `let score = 1;` и `const message = "ок";`

Почему: ты сам через неделю не вспомнишь, что сейчас лежит внутри. Типы подробно — в 🔗 теме 4.

---

### Вопросы

**Q1: Чем `let` отличается от `const`?**

Оба создают переменную с именем. `let` разрешает позже написать `имя = новоеЗначение`. `const` такое присваивание запрещает — движок выдаст ошибку. Для значений, которые не должны меняться (имя города, лимит попыток, текст кнопки), бери `const`. Для того, что накапливается или обновляется — `let`.

**Q2: Почему в этом курсе нет `var`?**

`var` старше и ведёт себя иначе: другая видимость, легче случайно использовать имя не там. Современный код пишут на `let`/`const`. Junior-цель — одна понятная модель. `var` встретится в легаси; не делай его привычкой.

**Q3: Можно ли создать переменную без значения?**

`let n;` создаст коробку, внутри будет `undefined` (🔗 тема 7). `const` без значения сразу при объявлении нельзя — константе нужно что положить. Практичнее сразу дать понятное значение, даже ноль или пустую строку, если это осмысленный старт.

**Q4: Что будет, если дважды объявить одно имя через `let` в одном месте?**

Ошибка вроде «уже объявлено». Имя в одной области занято. Либо используй то же имя без второго `let` (`count = 2`), либо выбери другое имя. Области видимости глубже — в 🔗 теме 13.

**Q5: `const` значит, что число на экране никогда не изменится для пользователя?**

Нет. `const` запрещает *переменной* получить другое значение. Текст на странице можно сменить другим кодом. Позже у объекта с `const` можно менять поля. Запоминай так: `const` защищает привязку имени, а не весь мир вокруг.

### Теория с аналогией

**Аналогия: вопрос и приказ**

- **Выражение** — фраза, у которой есть *результат*, как ответ на вопрос «сколько?» / «что это?». `2 + 3` даёт `5`. `"Привет"` даёт строку. Имя переменной даёт то, что в коробке.
- **Инструкция** (statement) — приказ «сделай шаг»: объяви переменную, выведи в консоль, позже — `if`, цикл.

Как мы видели в 🔗 теме 2, строка `const city = "Казань";` — инструкция объявления. Справа `"Казань"` — выражение (значение). Слева — имя коробки.

```javascript
let a = 2;          // инструкция: создай коробку a
let b = 3;          // инструкция
let sum = a + b;    // инструкция; a + b — выражение, результат 5
console.log(sum);   // инструкция: вызови функцию с выражением sum
```

Точка с запятой в современном JS часто ставится автоматически, но для учёбы полезно **завершать инструкцию `;`**, пока глаз не привык, где кончается шаг.

**Выражение можно вложить, инструкцию — нет как значение**

```javascript
console.log(1 + 2);     // ок: внутри скобок выражение 3

// console.log(let x = 1);  // нельзя: let — инструкция, не значение
```

Пока достаточно правила: *то, что кладём в переменную или передаём в `console.log`, должно быть выражением* (число, строка, имя, арифметика).

**Комментарии — записка человеку, движок их пропускает**

```javascript
// Одна строка: движок игнорирует до конца строки

const tax = 0.2; // можно в конце строки: зачем 0.2

/*
  Несколько строк.
  Удобно временно отключить кусок кода.
*/
```

Комментарий не меняет результат запуска из темы 1. Он меняет, поймёт ли коллега (или ты через месяц), *зачем* здесь `const tax = 0.2`.

Пиши «почему», не «что». Плохо: `// присваиваем tax`. Хорошо: `// доля НДС для чека, не путать с процентами на экране`.

**Схема**

```
инструкция:   const sum = a + b;
                    │       └── выражение (даёт число)
                    └── приказ «создай константу»

комментарий:  // ...   ← движок перепрыгивает, человек читает
```

---

### Где это в реальном коде

- Расчёт суммы в Node: `const total = price * count` — справа выражения, строка целиком — инструкция.
- Подсказка в учебном файле: `// TODO: подставить имя из формы` (форма — 🔗 тема 19).
- Отладка: временно `// console.log(total)` — выключили вывод, не удаляя строку.
- HTML не заменяет комментарии JS: `<!-- -->` — это HTML. В `.js` только `//` и `/* */`.

---

### Паттерны

**1. Один шаг — одна мысль в строке, пока учишься**

Так лучше не делать: `let x = 1; let y = 2; console.log(x + y);` в одну кашу без пробелов и смысла.

Так лучше: объявления отдельно, вывод отдельно.

Почему: ошибку проще найти. Позже можно уплотнять, когда глаз видит границы инструкций.

**2. Комментарий объясняет решение, не пересказывает код**

Так лучше не делать: `let n = 0; // n равно нулю`.

Так лучше: `let retryCount = 0; // сколько раз уже пробовали отправить форму`.

Почему: код и так видно. Комментарий нужен, когда имя не вмещает контекст.

**3. Не оставляй закомментированные простыни «на потом»**

Так лучше не делать: полфайла в `/* старая версия */`.

Так лучше: удалить или коротко отметить `// временно выключено: ломает запуск в Node`.

Почему: через неделю никто не знает, живой это код или археология.

### Вопросы

**Q1: Чем выражение отличается от инструкции?**

Выражение *даёт значение*: его можно положить в переменную или передать в `console.log`. Инструкция *делает действие*: объявляет имя, запускает вывод, позже ветвление. Путаница начинается, когда ждут результат от приказа, как от числа. Запомни: справа от `=` всегда выражение.

**Q2: Обязательна ли точка с запятой?**

Движок часто вставляет её сам, но правила вставки неочевидны и иногда ломают код. Пока учишься, ставь `;` в конце инструкции. Это снимает целый класс сюрпризов. В команде могут быть другие правила — тогда следуй файлу проекта.

**Q3: Видит ли пользователь сайта комментарии в `.js`?**

В исходном файле — да, если скачает скрипт (в DevTools исходники видны). На экране страницы комментарии не рисуются. Это не секретность: не клади в комментарии пароли. Для учёбы комментарий — записка себе.

**Q4: Можно ли вложить выражение в выражение?**

Да. `console.log((2 + 3) * 4)` — сначала `2 + 3` даёт `5`, потом умножение, потом вывод. Скобки задают порядок, как в арифметике. Инструкцию `let` внутрь `console.log` вложить нельзя.

**Q5: Чем `//` отличается от `/* */`?**

`//` действует до конца текущей строки. `/* ... */` может закрыть несколько строк, пока не встретится `*/`. Для одной мысли хватает `//`. Блок удобен, чтобы временно выключить кусок при отладке. Нельзя надёжно вкладывать `/*` внутрь другого `/*` — легко потерять закрытие.

Напиши файл `expressions.js`.

5. Добавь закомментированную строку с попыткой `console.log(let x = 1)` и в комментарии своими словами напиши, почему так нельзя.

const price = 150;
const count = 3;

console.log(total);

// console.log(let x = 1);
