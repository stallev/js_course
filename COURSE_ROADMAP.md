# Стратегия репозитория: Junior → TypeScript → Middle

Документ фиксирует решение разделить обучение на слои и описывает перенос уже существующего курса.

**Статус:** этапы A–H выполнены. Дальше — этап D (уточнение стандарта junior), если понадобится.

---

## Зачем два курса

Текущие материалы — курс **JavaScript для Middle FullStack Interview** (Next.js · React · TypeScript). Он начинается с Event Loop и TDZ, в каждой теме есть блок «связь со стеком», практика на TypeScript и React.

Junior нельзя получить, вырезав TypeScript из тех же файлов:

- другая дуга обучения (сначала переменные, типы, DOM; движок — позже);
- другая глубина (без интервью-головоломок и паттернов уровня middle);
- другой стек (чистый `.js`, без React/Next/TS).

Middle **не переписывается** под junior. Его ценность — глубина и стек. Junior — новый курс.

---

## Три слоя

| Слой | Цель | Стек | Чего нет |
|------|------|------|----------|
| **Junior** | Научиться писать и читать JavaScript | Браузер + Node, только `.js` | TypeScript, React, Next, интервью-уровень «магии» |
| **TypeScript** | Типы поверх уже понятого JS | TS без React | Хуки, Fiber, Redux |
| **Middle** (то, что уже есть) | Интервью Middle FullStack | Next · React · TS | Повторение азбуки языка с нуля |

Порядок прохождения: Junior → TypeScript → Middle.

Явные решения:

- **DOM в junior обязателен** — иначе курс слишком академический.
- **Нумерация тем своя** у каждого курса. Junior не использует номера 1–45 middle.
- **Тексты** `section_1`–`section_8` middle **не копировать** как основу junior. Аналогии и схемы можно брать точечно позже, переписывая тон.
- **TypeScript — третий каталог** (`typescript/`), не финальный раздел junior.

## План переноса (этап A)

Существующий курс переезжает целиком, чтобы сохранить git-историю:

```
git mv general  middle/general
git mv topics   middle/topics
git mv sandbox  middle/sandbox
```

Ссылки `../general/...` внутри `topics/` и `sandbox/` после совместного переезда остаются валидными.

Чинить нужно пути **от корня репозитория**:

- `package.json`: `sandbox/next_sandbox`, `sandbox/js_sandbox` → `middle/sandbox/...`
- `.gitignore`: то же
- команды `npx tsx sandbox/...` в инструкциях и комментариях упражнений → `middle/sandbox/...`

Корневой `README.md` становится коротким хабом. Полный текст middle-курса живёт в `middle/README.md`.

## Этапы A–H

| Этап | Содержание | Статус этой итерации |
|------|------------|----------------------|
| **A** | Перенос в `middle/`, хаб README, починка корневых путей | Сделано |
| **B** | Каркас `junior/` (стандарт темы, sandbox-заглушки) | Сделано |
| **C** | Список тем junior с зависимостями | Сделано |
| **D** | Полный стандарт качества junior (уточнение по ходу первых разделов) | Позже |
| **E** | Писать разделы теории по одному | Сделано: разделы 1–9 (темы 1–26) |
| **F** | Упражнения `.js` + браузерный раннер | Сделано |
| **G** | Каталог `typescript/` — мост перед middle | Сделано: 14 тем, 5 разделов + sandbox `.ts` |
| **H** | Middle оставить входом «уже пишу React/TS, готовлю интервью»; в README явно указать порядок слоёв | Сделано: хаб, `middle/README`, оглавление, вход раздела 1 и пометка у темы 24; темы 1–28 не переписывались |

Чего не делать:

- не «опускать» middle правками тех же markdown;
- не оставлять `.ts` в junior «для удобства»;
- не тащить темы 29–45 middle в junior;
- не копировать тему 24 Middle как текст слоя `typescript/`;
